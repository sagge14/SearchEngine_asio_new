Настройки сервера

Файл называется Settings.json. Все поля лежат в разделе config.

В комплекте data\Settings.json — шаблон. Его можно поправить до установки. После установки рабочий файл находится в каталоге данных службы. Меняет поведение только он. Установленный файл удобнее править через Configure-SearchEngineService.bat: скрипт проверяет JSON, перезапускает службу и при ошибке возвращает прежний файл. Правка вручную тоже читается только после перезапуска службы.

Не удаляйте незнакомые поля. Если обязательного поля не хватает, служба может не запуститься. Если не хватает необязательного, при старте оно будет дописано значением по умолчанию.

Индекс всегда лежит рядом с настройками в файле inverted_index.sqlite. Имя этого файла в настройках не задаётся.

Пути index_roots и excluded_subtrees — абсолютные локальные пути или UNC, например D:\DATA и \\server\share\DATA. Каталог может ещё не существовать. Остальные пути ниже — абсолютные локальные, без UNC. Букву сетевого диска сеанса пользователя, например Z:\, для службы не используйте: служба её не видит.

Рабочие настройки

Их меняют, когда нужно указать год, порт, папки, типы файлов или базы.

ПолеЗачем
yearГод баз. Сервер открывает помесячные файлы MM-ГОД.db3, опись ГОД.db и маршруты ГОД.db. Смена года не переносит файлы на диске.
asio_portПорт, на котором сервер принимает клиентов. Тот же номер нужен в клиенте. У двух служб на одном компьютере порты должны различаться.
index_rootsПапки, которые сервер индексирует вместе со вложенными. Пустой список недопустим.
excluded_subtreesВетки внутри этих папок, которые индексировать не нужно. Пустой список значит «исключений нет».
indexed_extensionsКакие типы файлов брать. Расширение пишется без точки: txt, не .txt. Регистр не важен.
include_extensionless_filesБрать ли файлы без расширения. Если расширений нет совсем, это поле должно быть true.
query_word_matchall — в документе должны быть все слова запроса. any — достаточно любого.
max_responseСколько лучших ответов отдать клиенту. Ноль отдаёт пустой список, а не все результаты.
ind_timeКак часто делать полный проход по папкам, в секундах. 1500 — это 25 минут. Минимум 1.
scan_on_startuptrue — полный проход сразу после старта. false — ждать первого срабатывания ind_time.
server_modeactive — живой сервер: следит за папками и обновляет индекс. archive — замороженный комплект: слежение и таймер выключены, оперативная база ARCHIVE.db3 не открывается.
document_catalog_storageГде держать список путей файлов. memory — в оперативной памяти. sqlite — в файле индекса, без полной загрузки списка в память. Для archive нужно sqlite.
prm_base_dirКаталог баз входящих. Пустая строка выключает входящие, служба при этом запускается.
prd_base_dirКаталог баз исходящих. Пустая строка выключает исходящие.
prm_monthly_bases_dirГде лежат помесячные входящие MM-ГОД.db3. Если поля нет, берётся prm_base_dir\METH_BASES.
prd_monthly_bases_dirТо же для исходящих. Если поля нет, берётся prd_base_dir\METH_BASES.
opis_base_dirКаталог описи. Имя файла сервер собирает сам: ГОД.db.
f12_base_dirКаталог маршрутов. Читается ГОД.db. Файл base.db в том же каталоге дополняет только текущий календарный год.
tlg_send_rootКуда складывать телеграммы к отправке: внутри появятся папки месяца и даты.
razn_output_dirКуда складывать файлы разноски.
hide_console_windowСпрятать консольное окно при ручном запуске программы. На службу Windows не влияет.
enable_prm_short_content_autodetectПри появлении нового входящего файла дописывать краткое содержание в базу PRM. Имеет смысл только в режиме active и при заданном prm_base_dir.

Год и список папок решают разные задачи. year выбирает базы. index_roots выбирает файлы телеграмм.

Режим archive вместе с годом используют для комплекта, который не должен пополняться. Вместе с ним ставьте document_catalog_storage в sqlite.

Отсутствие каталога описи, F12, разноски или отправки не мешает запуску поиска. Ошибка появится, когда вызовут соответствующую команду.

Тонкая настройка

Эти поля меняют скорость, нагрузку на диск и память. На обычной машине оставьте значения из шаблона.

ПолеЗачем
thread_countСколько потоков отдать расчётам. 0 — по числу ядер. 1 ставить нельзя.
max_parallel_readersСколько файлов читать с диска одновременно. 0 — без ограничения. Для обычного жёсткого диска часто достаточно 1.
file_indexing_timeout_secСколько секунд ждать один файл при полном проходе. Допустимо от 10 до 600. Файл, не уложившийся в срок, пропускается, проход идёт дальше.
compact_threshold_percentПри каком проценте пустых ячеек в словаре уплотнять индекс после полного прохода. На файлы и базы AutoPad не влияет.
full_index_strategyКак собирать ещё пустой индекс: batch — конвейером, legacy — пофайлово. На уже заполненном индексе обновление идёт пофайлово в обоих случаях.
batch_reader_threadsСколько потоков читают файлы при первой сборке конвейером. Для обычного диска обычно 1.
batch_indexer_threadsСколько потоков разбирают текст при первой сборке. 0 — все ядра.
batch_queue_memory_mbСколько мегабайт уже прочитанного текста держать в очереди, пока разбор не успевает.
sqlite_mirror_flush_interval_secКак часто, в секундах, записывать накопившиеся изменения индекса на диск.
sqlite_mirror_max_pending_opsЗаписать изменения сразу, если очередь стала длиннее этого числа. 0 — писать только по таймеру.
sqlite_load_threadsСколькими соединениями читать индекс при старте службы. 1 — строго по очереди.
sqlite_precount_postingsПеред загрузкой индекса заранее посчитать вхождения, чтобы выделить память пачкой. Включайте только если замерили, что так старт быстрее.

Поля batch_* относятся к первой сборке пустого индекса при стратегии batch. На ежедневный поиск они не влияют.
