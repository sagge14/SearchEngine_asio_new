Дополнение и перезапись файла

Прямое чтение прежних имён параметров само по себе не запускает перезапись. Отсутствие server_mode означает active без обязательного пересохранения; отсутствие месячного пути выводит его из корня также без обязательной перезаписи.

Но отсутствие ряда других необязательных полей запускает полное сохранение канонического файла. Тогда прежние имена параметров и незнакомые поля могут исчезнуть. Не используйте запуск с неполным JSON как способ сохранить дополнительные поля. Обязательны год, корни индекса, выбор типов файлов и строки prm_base_dir/prd_base_dir; пустая строка PRM/PRD — штатное отключение, отсутствие строки — ошибка.

ind_time при отсутствии получает 0, а проверка старта требует ≥1: оставляйте его явно. Это конкретная особенность текущего чтения, а не обещание автоматического восстановления любого неполного файла.

Обновление через установщик

Штатная переустановка начинает с нового шаблона, рекурсивно переносит существующие установленные значения, а затем учитывает явные ответы диалога. Новые поля получают значения нового шаблона. Индекс и прочее состояние в каталоге данных сохраняются. Необязательный экспорт — отдельная копия оператора; отказ от него не означает очистку ProgramData.

Если файл редактируется мастером, используются канонические имена. Проверка Configure/Install строже прямого чтения: например диапазон года 2000…2099, положительный интервал SQLite и архитектурный предел потоков. Не полагайтесь на возможность запуска обходным способом с отвергнутыми мастером значениями.

Учебная проверка при переносе

  1. Сохраните исходный файл отдельно; не используйте рабочие базы для демонстрации.
  2. Замените старые имена на новые, устраните дубли port/asio_port, проверьте все обязательные поля.
  3. Примените через Configure и сверяйте фактический год/порт.
  4. Проверьте текст, SQL, нужные детали и файлы отдельно. Один PONG их не проверяет.
