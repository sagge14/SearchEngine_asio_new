Вернуть сервер из архива

Цель: Снова обслуживать прежний год в active с автоматическим обновлением.

Условия

Целый архивный комплект с archive-operation.json, существующая служба, всё ещё запускающаяся из него, полный пакет и права администратора на том же ПК. Для обычного поиска архив размораживать не требуется.

До подтверждения выберите безопасное место. Если исходные папки заняты следующим годом, используйте отдельный корень. При возврате в исходные места сохранённая для TverdakManager декабрьская PRD заменяется восстановленной SQLite-копией без отдельного вопроса. Отдельные изменения в ней не объединяются с архивом.
Подтверждённое удаление уничтожает весь конкретный архивный комплект с документами, базами и manifest. Проверки мастера не выявляют все внешние приложения. Пункт Archive → 2 → 3 предназначен для прежних источников работающей архивной службы; для позднего удаления копии после разморозки он не подходит.

Действия

  1. Остановите изменение документов и баз другими программами. Подготовьте место для восстановленной копии и определите, свободны ли прежние назначения.
  2. Запустите Archive-SearchEngineService.bat от администратора: «2 — Архивировать/разморозить службу» → «2 — Вернуть и разморозить».
  3. Укажите конкретный комплект экземпляра с manifest, например E:\SearchArchive\SearchEngineService-2026, а не общий корень.
  4. Выберите «1 — исходные места» либо «2 — выбранный каталог». Прочитайте весь план и условия существующих файлов и декабрьской PRD. Новый корень может существовать; показанные целевые папки режима 2 должны отсутствовать.
  5. Подтвердите возврат и дождитесь запуска. Прежние имя службы, год и порт сохраняются.
  6. На вопрос об удалении архива пока не отвечайте. Найдите входящий и исходящий документ, откройте их из восстановленного места, проверьте SQL, TverdakManager, внешние опись/F12 и удалённое подключение. Проверьте правило брандмауэра для восстановленного EXE.
  7. Вернитесь к мастеру. Сохраните архив, если проверка не завершена или внешнее приложение ещё использует его. Удаление подтверждайте только после проверки всех зависимостей.

Ожидаемый результат

Та же служба работает в active из восстановленного места. При подготовке новой копии scan_on_startup=false: полный проход не обязан начинаться сразу. При возврате без прежней очистки сохраняется исходная конфигурация.

Если возникла ошибка

Не удаляйте архив. Прочитайте, откуда сейчас запускается служба: ошибка очистки может возникнуть уже после успешного возврата. Несовпадающие файлы не сливаются; выберите отдельный корень. Настройте внешние приложения на новые пути отдельно.
