Два режима доступа к серверу

Быстрая установка без вопросов: Local-Install-With-Auth.bat — с авторизацией; Local-Install-Without-Auth.bat — без ключей и токенов. Запустите нужный файл; при запросе Windows подтвердите права администратора. Год, свободный порт, индексация и запуск службы выбираются автоматически. Это новая местная установка; для обновления существующей службы используйте обычный Install.

Режим выбирается для каждого экземпляра сервера отдельно. Можно работать с токенами или предоставить общий доступ без выпуска ключей и регистрации компьютеров.

Выбор при установке

  1. Для новой местной установки запустите Local-Install-With-Auth.bat или Local-Install-Without-Auth.bat. Режим задаётся автоматически. Для настройки с вопросами запустите обычный мастер Install.
  2. Только в обычном мастере на вопрос «Доступ к серверу» выберите 1 — С авторизацией или 2 — Без авторизации и ключей. Enter сохраняет предложенный вариант. При обновлении обычный мастер предлагает сохранённый режим.
  3. Дождитесь завершения установки и запишите адрес и порт службы.
  4. В SearchClient выберите выданный токен для защищённых серверов или Без авторизации для открытых, затем нажмите Подключение.

Батник Local-Install-With-Auth создаёт и регистрирует токен этого ПК. В Local-Install-Without-Auth этот шаг пропускается: ключи издателя, подпись и токен не создаются. Первоначальная индексация выполняется в обоих вариантах.

Изменение действующей службы

Штатно остановите нужную службу, откройте её рабочий Settings.json и измените поле внутри config:

"authentication_mode": "none"

none разрешает запросы без авторизации. Для возврата к токенам задайте "authentication_mode": "required" и подготовьте разрешения и открытый ключ обычным способом. Запустите службу и переподключите клиент. Изменение применяется после перезапуска; индекс перестраивать не требуется.

Если поля нет, используется required. Другие значения считаются ошибкой. Отсутствие или повреждение файлов авторизации само по себе общий доступ не включает. В режиме none существующие файлы авторизации сохраняются и не открываются сервером.

Что записывается в журнал

У всех запросов открытого сервера имя unauthenticated_user. В журнале сохраняются дата, время, действие и отдельный IP-адрес TCP-клиента. Переданное клиентом имя не заменяет это значение. Старые записи журнала сохраняются; у них новый столбец IP может быть пустым.

IP показывает сетевой источник, а не удостоверяет человека. Доступ получает любой компьютер, которому доступен порт этого экземпляра. Ограничьте нужную сеть настройками брандмауэра.

Файлы и обслуживание

Поиск, тексты, приложения карточек, опись и загрузка файлов доступны без токена. Загрузка на отправку использует общее имя unauthenticated_user в папке оператора; имя настоящего оператора не определяется.

Персональная служебная команда получения одноразового пакета использует только запись unauthenticated_user в prefix_map.json. Если записи нет, операция возвращает ошибку. При её добавлении буфер станет общим для всех подключений. Этот буфер удаляется после чтения, до передачи ответа: сначала сохраните отдельную копию. Это ограничение не относится к обычным приложениям карточки.

В архивном режиме автоматическая индексация выключена. Ручное обслуживание индекса открытого архива разрешено только с 127.0.0.1 без токена; на защищённом архиве нужен местный admin. Передача имени admin с другого адреса прав не добавляет.

Проверка

  1. В клиенте без токена выберите «Без авторизации» и подключитесь к открытому экземпляру.
  2. Проверьте строку «доступно серверов K/N, без авторизации: M», найдите известный документ и откройте текст.
  3. Проверьте в журнале имя и IP. После переключения в required подключение без токена должно быть отклонено.
