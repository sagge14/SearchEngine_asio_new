Утрачен пароль ключа издателя

Это руководство относится к серверам authentication_mode=required. Для режима none выпуск ключей и токенов не требуется: работа без авторизации.

Быстрый маршрут: Подключить дополнительный ПК после настройки доступа

Это руководство нужно администратору главного ПК, который выдаёт токены доступа. Если пароль закрытого ключа утрачен, новые устройства подписать нельзя. Для восстановления выдачи создаётся новая пара ключей, существующим устройствам выдаются новые токены, затем серверы переключаются на новый открытый ключ.

Старые ключи в резервные копии не сохраняются. После подготовки перевыпуска прежнее хранилище заменено. Отменить это действие возвратом старого ключа нельзя. Базы документов, индекс и базы разрешений устройств не удаляются.

1. Убедитесь, что нужен именно перевыпуск

Пароль нужен для подписи новых токенов, а не для обычного подключения клиента. Старые токены продолжают проходить проверку серверов с прежним открытым ключом. Ошибка одного клиента сама по себе не означает утрату пароля.

Если ключ создавался упрощённым Local-Install-With-Auth.bat, штатный пароль созданного им хранилища — 12345678. Это относится к созданному этим установщиком ключу: существующее хранилище с другим паролем он не перезаписывает. При действительно утраченном пароле переходите к шагу 2.

2. Подготовьте новый ключ на главном ПК

  1. Запустите Setup-Access.bat от имени администратора под той же учётной записью Windows, которая использовалась для главного ПК.
  2. Выберите 6 — Утрачен пароль: подготовить перевыпуск ключей.
  3. Мастер берёт устройства из access-authority.json, баз разрешений включённых в главную систему местных служб и местного токена ПК. Показывает число устройств. Если главная система ещё не сохранена, сначала выберите роль ПК и местные серверы. Данные клиентов собираются без удаления исходных записей.
  4. Подтвердите подготовку. Задайте новый пароль и повторите его. Запишите его в надёжном месте.
  5. Дождитесь сообщения о подготовленных ключах и токенах. На этом шаге службы не останавливаются и не переключаются.

Закрытый ключ находится в %ProgramData%\SearchClientTokenIssuer\keys\private.enc.pem, открытый — в public.pem. Каталог устройств главного ПК обновляется новыми подписями, сохраняя идентификатор клиента, имя, тип устройства и его привязку. Пароль в каталог и токены не записывается.

Если старая служба проверяла подписи через общий файл public.pem, мастер перед его заменой устанавливает прежний действующий открытый ключ в обычный файл доверия службы <data-dir>\issuer-public.pem. Поэтому её старые токены продолжают работать до переключения этой службы. Дополнительный резервный файл ключа не создаётся.

3. Замените токены компьютеров

  1. На каждом клиентском ПК выберите 2 — Подготовить заявку этого ПК. Сохраните и перенесите заявку на главный ПК. Существующий токен оставьте на месте: из него берутся прежние имя и идентификатор.
  2. На главном ПК выберите 3 — Обработать заявку. Сохраните новый ответ. В период подготовленного перевыпуска обработка заявки не переключает местные серверы.
  3. На клиентском ПК выберите 4 — Применить ответ. Если на нём есть сервер, на вопрос об установке ключа на местные серверы выберите 0, чтобы пока установить только токен ПК.
  4. Главный ПК, если на нём используется SearchClient, также проведите через заявку и ответ. Имя Windows само по себе не заменяет токен доступа.

После замены токена клиент сможет пройти новую авторизацию только на сервере, который уже принимает новый ключ. Планируйте замену токенов и переключение серверов в одно удобное окно: временный перерыв доступа возможен. Точная прежняя идентичность сохраняется; исключение — старый общий идентификатор local-machine, для которого действующий механизм заявок создаёт уникальный идентификатор ПК.

4. Замените токены флешек

  1. Подключите исходную флешку к главному ПК. На ней должен находиться действующий по структуре файл searchclient-auth-token.json.
  2. Выберите в Setup-Access.bat 8 — Перевыпустить существующий токен флешки. Альтернатива — пункт 5 в Issue-SearchClientToken.bat.
  3. Выберите накопитель. Утилита сверяет аппаратный серийный номер флешки с привязкой токена и показывает сохраняемые имя и идентификатор. При несовпадении запись запрещена.
  4. Подтвердите замену и введите новый пароль издателя. Новый токен записывается в корень той же флешки. Его привязка и идентификатор сохраняются.

Если записи этой флешки не было в каталоге главного ПК или его местных базах, зарегистрируйте новый токен на нужных серверах через Register-AuthClient-FromToken.bat после переключения ключа. Повторная регистрация существующей записи сохраняет её отключённое состояние. Режим перевыпуска предназначен для известного администратору устройства; исходный токен берите из доверенного источника.

5. Переключите серверы

  1. На главном ПК выберите 7 — Переключить местные серверы на ключ главного ПК. Выберите одну службу либо все перечисленные. Сверьте отпечаток ключа и подтвердите переключение.
  2. Мастер устанавливает новый issuer-public.pem и обновляет сведения о токенах в auth_clients.sqlite. Существующие разрешения сохраняются, отключённые записи не включаются. Работающие службы перезапускаются, остановленные остаются остановленными.
  3. Для остальных местных служб повторите пункт 7. На удалённых серверных ПК примените новый ответ через пункт 4, теперь согласившись установить ключ на серверы. Для применения только на серверах можно использовать ответ, адресованный другому клиентскому ПК: его местный токен при этом не заменяется.
  4. Включите в проверку архивные службы прошлых лет. В группе клиента могут находиться серверы разных лет, и каждый проверяет подпись самостоятельно.
На одном сервере действует один ключ проверки. После переключения и перезапуска прежняя подпись будет отклоняться, даже если устройство осталось в базе разрешений. Сохранённая запись разрешения и подходящая подпись нужны одновременно.

6. Проверьте результат

Пункт 5 — Проверить локальные разрешения проверяет местный токен на выбранных службах. Затем в SearchClient заново выполните подключение и проверьте результат авторизации всех серверов группы. Проверка без местного токена показывает ключ и количество включённых записей, но не подтверждает доступ конкретного клиента.
