Практические примеры настройки сервера

Быстрый маршрут: Изменить настройки

Все значения и каталоги ниже учебные. Изменяйте нужные поля в полной копии файла, не заменяйте весь Settings.json приведённым фрагментом. Применение выполняется через Configure, после перезапуска проверяется нужная пользовательская функция. Допустимые значения: единый справочник.

Подключить второй экземпляр

{
  "asio_port": 16006
}

У экземпляров разные каталоги данных и свободные порты. Configure обновляет правило брандмауэра и подсказку; в клиенте укажите тот же port.

Ожидаемый результат: List показывает открытый 16006, клиент авторизует новый источник.

Типичная ошибка: Меняется только шаблон пакета; в старом конфиге остался port; адрес клиента не обновлён.

Искать только нужные ветки

{
  "index_roots": [
    "E:\\Учебный_архив"
  ],
  "excluded_subtrees": [
    "E:\\Учебный_архив\\OUT"
  ]
}

Положите учебные слова в OUT и соседнюю OUTSIDE. year не выбирает папки документов.

Ожидаемый результат: После обновления слово из OUTSIDE доступно, слово только из OUT не должно попасть в новый учебный индекс.

Типичная ошибка: Исключение записано как маска *.txt или относительный путь; нет прав учётки службы; проверяется старый индекс без полного обновления.

Выбрать типы файлов

{
  "indexed_extensions": [
    "txt"
  ],
  "include_extensionless_files": false
}

Для одних файлов без расширения задайте пустой массив и true.

Ожидаемый результат: file.txt и FILE.TXT индексируются, file.mytxt и README в этом примере нет.

Типичная ошибка: Расширение .txt, дубли TXT/txt, пустой список вместе с false.

Все слова или любое

{
  "query_word_match": "all",
  "max_response": 100
}

Учебные документы: «проверка связи» и «проверка оборудования». Запрос «проверка связи», без кавычек и внешних точек.

Ожидаемый результат: При all подходит первый. При any подходят оба. Точная форма «проверки» — другое слово; знак * не задаёт окончания.

Типичная ошибка: Пользователь переключает SQL-точность, ожидая изменить текстовый all/any; разные источники настроены по-разному.

Месячные входящие отдельно, исходящие выключены

{
  "prm_base_dir": "E:\\Учебные_базы\\PRM",
  "prm_monthly_bases_dir": "E:\\Учебные_месяцы\\PRM",
  "prd_base_dir": ""
}

В учебном профиле поместите нужные месяцы 01…13-ГОД.db3 в явный каталог.

Ожидаемый результат: В active SQL Вх. читает заданные месяцы, SQL Исх. пуст; карточки текста выключенного источника тоже не выдаются. В archive для выключения Исх. обнулите также prd_monthly_bases_dir.

Типичная ошибка: Удалён ключ prd_base_dir вместо пустой строки; не учтено, что явный месячный каталог включает источник в archive, но не в active.

Закрытый год без автоматического обновления

{
  "year": "2025",
  "server_mode": "archive",
  "document_catalog_storage": "sqlite"
}

Этот фрагмент задаёт режим. Физический перенос установленной службы делайте архиватором.

Ожидаемый результат: Поиск прежнего года доступен, watcher/таймер/стартовый проход отключены, ARCHIVE.db3 не читается.

Типичная ошибка: Изменён лишь year, ожидался перенос папок; archive оставлен с memory.

Первый проход позже

{
  "scan_on_startup": false,
  "ind_time": 1800
}

Пример только для active; 1800 секунд = 30 минут.

Ожидаемый результат: По журналу нет полного стартового прохода, первый плановый наступает позже. Слежение за изменениями остаётся.

Типичная ошибка: false принято за отключение всей индексации; PONG принят за окончание полного прохода.

Сравнить первую сборку

{
  "full_index_strategy": "batch",
  "batch_reader_threads": 1,
  "batch_indexer_threads": 0,
  "batch_queue_memory_mb": 256
}

Используйте отдельный пустой индекс и одинаковый учебный набор.

Ожидаемый результат: В журнале первой сборки указан batch; параметры очереди и потоков применены.

Типичная ошибка: Удалён рабочий индекс ради теста; сравнивается уже заполненный индекс, который обновляется пофайлово.

Проверить частоту записи SQLite

{
  "sqlite_mirror_flush_interval_sec": 1.0,
  "sqlite_mirror_max_pending_ops": 100
}

Изменение влияет на частоту записи; выбор каталога memory/sqlite этим не задаётся.

Ожидаемый результат: В тестовом журнале изменения сбрасываются по таймеру или при достижении 100 операций; после штатной остановки индекс повторно читается.

Типичная ошибка: 0 задан как «не писать»; измеряется лишь число ответов поиска.

Если изменение не применилось

Уточните службу и её фактический рабочий каталог данных, проверьте итог Configure и журнал старта. Для повреждённого JSON верните читаемую полную копию. Для занятого порта выберите свободный и согласуйте клиент. Для недоступных файлов проверьте права учётной записи службы, типы и корни. При частично авторизованной группе успешный поиск одного источника не проверяет остальные.

Для SearchEngineService 0.1.99. Редакция 30 октября 2026 года. Все примеры учебные.
