# Конфигурации резервного копирования AutoPad

Каталог подготовлен для отмеченных на скриншоте источников:

- `D:\BASES`;
- `D:\BASES_PRD`;
- `D:\F12`;
- `D:\OTPRAVKA`;
- `D:\TVRD`.

## Какой файл использовать

Рекомендуемый вариант — один процесс BackupService и файл
`Backup.all.json`.

Файлы `Backup.databases.json` и `Backup.programs.json` содержат ту же
конфигурацию, разделённую для двух процессов. Их можно использовать вместо
`Backup.all.json`, но нельзя одновременно запускать объединённый и
раздельные варианты: тогда одни и те же источники будут резервироваться
дважды.

Перед запуском замените все значения:

```text
F:\AutoPadBackups
```

на нужный диск и каталог хранения.

Запуск:

```text
BackupService --config tools\backup\configs\autopad\Backup.all.json
```

Проверка без постоянного планировщика:

```text
BackupService --config tools\backup\configs\autopad\Backup.all.json --once
```

## Расписание

| Источники | Интервал | Версий | Политика |
|---|---:|---:|---|
| `BASES\ARCHIVE.db3`, `BASES_PRD\ARCHIVE.db3`, `F12\base.db`, `F12\2026.db` | 1 минута | 180 | без кэша, не создавать неизменившиеся |
| `BASES\JURNAL.db3`, `BASES_PRD\PARAMETERS.db3` | 15 минут | 96 | без кэша, не создавать неизменившиеся |
| `OTPRAVKA\Settings*.db3` | 1 час | 168 | без кэша, не создавать неизменившиеся |
| `TVRD` целиком | 5 минут | 2016 | без кэша, не создавать неизменившиеся |
| `BASES`, `BASES_PRD` целиком | 1 час | 168 | проверенный кэш, полный снимок |
| `F12`, `OTPRAVKA` целиком | 6 часов | 120 | проверенный кэш, полный снимок |

`max_versions` считает только реально созданные версии. Если источник не
изменился, `skip_unchanged: true` сохраняет прежний снимок и не расходует
новое место.

При максимальной активности приблизительный верхний предел одновременно
хранимых данных составляет около 26 ГБ. Фактический объём будет меньше,
поскольку неизменившиеся цели новых версий не создают.

## Почему интервалы разные

Активные SQLite копируются часто и сразу в снимок. `cache: false` исключает
вторую запись того же файла на резервный диск.

`TVRD` занимает всего несколько килобайт, поэтому полный пятиминутный снимок
дешёвый.

Каталоги программ содержат исполняемые файлы, библиотеки, шаблоны и резервные
копии баз. Они меняются редко, поэтому достаточно полного снимка раз в шесть
часов. Если ничего не изменилось, новый снимок не создаётся.

## Восстановление

Перед восстановлением остановите программы и отключите сетевых пользователей.

Для `BASES` или `BASES_PRD`:

1. Восстановите содержимое `data` последнего полного снимка каталога.
2. Если отдельный снимок `ARCHIVE.db3` новее, скопируйте его
   `data\ARCHIVE.db3` поверх файла из полного снимка.
3. Для `BASES_PRD` аналогично можно наложить более свежий
   `PARAMETERS.db3`.

Для `F12`:

1. Восстановите последний полный снимок `F12`.
2. Наложите более свежие отдельные `base.db` и `2026.db`.

Для `OTPRAVKA`:

1. Восстановите последний полный снимок `OTPRAVKA`.
2. Наложите более свежие `Settings.db3`, `Settings2.db3` и `SettingsO.db3`.

Для `TVRD` достаточно целиком восстановить содержимое `data` выбранного
снимка.

В начале нового года обновите в конфигурации путь `D:\F12\2026.db` на файл
текущего года. Полный снимок `F12` продолжит включать новый файл независимо
от этой ручной настройки.
