# Экономный профиль AutoPad

`Backup.economical.json` — рекомендуемый профиль нового режима
`mirror_history` для:

- `D:\BASES`;
- `D:\BASES_PRD`;
- активных баз и полного каталога `D:\F12`;
- настроечных баз и полного каталога `D:\OTPRAVKA`;
- `D:\TVRD`.

Перед запуском замените `F:\AutoPadEconomicalBackups` на нужный каталог.

Проверочный запуск:

```text
BackupService --config tools\backup\configs\autopad-economical\Backup.economical.json --once
```

Постоянный запуск:

```text
BackupService --config tools\backup\configs\autopad-economical\Backup.economical.json
```

## Почему цели разделены именно так

`BASES` и `BASES_PRD` можно проверять целиком каждую минуту. Неизменившиеся
файлы в `current\data` не копируются заново, а SQLite проверяются отдельно и
снимаются через Online Backup только при необходимости.

В `F12` и `OTPRAVKA` есть не только базы, но и программы, DLL, шаблоны и
журналы. Чтобы каждую минуту не перечитывать весь каталог, активные базы
выделены в частые цели, а полные каталоги проверяются раз в час и раз в шесть
часов соответственно. Это означает небольшое осознанное дублирование
активных баз, зато сильно уменьшает постоянное чтение рабочего диска.

`TVRD` мал, поэтому сохраняется целиком каждые пять минут.

В начале нового года замените `D:\F12\2026.db` на файл нового года.

## Гибкие периоды истории

Для каждой цели список независимый:

```json
"history_periods": [
  {"every": "1min", "keep": 60},
  {"every": "1h", "keep": 48},
  {"every": "1d", "keep": 31},
  {"every": "1w", "keep": 12},
  {"every": "1mo", "keep": 12}
]
```

`every` задаёт минимальный интервал между точками, `keep` — сколько последних
точек этого интервала оставить. Единицы: `s`, `min`, `h`, `d`, `w`, `mo`.
`mo` сейчас считается как 30 суток. Минуты обозначаются `min`, поэтому
неоднозначности с месяцами нет.

`period_sec` группы задаёт частоту фактического запуска. Поэтому для правила
`10s` группа также должна запускаться не реже чем раз в 10 секунд.

Если для периода нужна одна точка, допустима короткая запись:

```json
"history_periods": "10s, 2min, 3h, 1d, 2w, 1mo"
```

или:

```json
"history_periods": ["10s", "2min", "3h", "1d", "2w", "1mo"]
```

## Что занимает место

`current\data` содержит один полный актуальный комплект файлов. При изменении
одного файла переписывается только он. Предыдущая версия этого файла
переносится в `objects\by-path` один раз.

Папки в `restore_points` содержат только небольшие `manifest.json`. После
ротации точек программа удаляет версии файлов, на которые больше не ссылается
ни одна оставшаяся точка. SHA-256 хранится для каждого снятого файла.

До появления отдельной утилиты восстановления актуальное состояние можно
восстановить обычным копированием `current\data`. Историческая сборка
описывается в `docs\BACKUP_MIRROR_HISTORY.md`.
