# Как настраивать сервер SearchEngine

Конспект к видеолекции. Все поля берутся из объекта `config` файла `Settings.json`. Назначение сверено с кодом сервера: разбор JSON, проверка при старте и места, где значение реально меняет поведение.

Подробная версия для показа и печати в PDF: [lecture-server-settings.html](lecture-server-settings.html).

Короткая версия для комплекта поставки: [SERVER_SETTINGS.html](../tutorials/SERVER_SETTINGS.html). Она копируется в релиз вместе с остальными инструкциями.

Как вести лекцию. Сначала покажите файл и скажите, что правка начинает действовать только после перезапуска. Затем пройдите карту «рабочие / тонкие». Основное время отдайте рабочим настройкам и сценариям «хочу, чтобы…». Тонкий блок в конце: эти поля существуют, обычно их не трогают, но вот зачем каждое.

## 1. Где лежат настройки и когда они включаются

Рабочий файл всегда лежит в каталоге данных экземпляра:

```text
data-dir\Settings.json
```

Каталог данных задаётся при запуске (`--data-dir`) или при установке службы. Это не поле внутри `Settings.json`. При старте сервер делает этот каталог текущим, поэтому индекс тоже оказывается здесь, под фиксированным именем `inverted_index.sqlite`. Путь к файлу индекса в настройках не задаётся.

Весь документ — объект с одним разделом `config`:

```json
{
  "config": {
    "year": "2026",
    "asio_port": 15006,
    "index_roots": ["D:\\ЯНВАРЬ", "D:\\TLG"],
    "indexed_extensions": ["txt", "atl", "shp"]
  }
}
```

Порядок при старте:

1. Процесс ищет `data-dir\Settings.json`.
2. Отсутствующие необязательные поля дописываются значениями по умолчанию, и файл перезаписывается в каноническом виде.
3. Настройки проверяются. Ошибка диапазона, пустой год, кривой путь или архивный режим без SQLite-каталога не дают серверу подняться.
4. Дальше значения живут в памяти до остановки. Повторного чтения файла на ходу нет.

Рядом в том же каталоге лежат другие файлы:

| Файл | Что это |
| --- | --- |
| `Settings.json` | Настройки поиска и путей этой лекции |
| `inverted_index.sqlite` | Сам поисковый индекс. Имя фиксировано |
| `Backup.json` | Отдельная конфигурация резервного копирования |
| `auth_clients.sqlite` | Клиенты авторизации |
| `prefix_map.json` | Карта префиксов вложений |
| `OEM866.INI` | Таблица перекодировки |

Если удалить необязательное поле, при следующем старте сервер допишет его сам и перезапишет весь `Settings.json` каноническими именами. Старые имена (`dirs`, `extensions`, `exact_search`, `hide_mode`, `exclude_dirs`, `port`) при таком пересохранении исчезнут.

Сохранили JSON — перезапустили службу или консольный процесс.

## 2. Две полки

Рабочие настройки меняют то, что видит оператор. Тонкие крутят скорость, диск и память. На обычной машине заводские значения уже рабочие.

### Рабочие

| Поле | Зачем |
| --- | --- |
| `year` | Год, по которому открываются базы телеграмм, описи и F12 |
| `asio_port` | TCP-порт, на котором сервер принимает клиентов |
| `index_roots` | Папки, которые сервер индексирует рекурсивно |
| `excluded_subtrees` | Ветки внутри этих папок, которые надо пропускать |
| `indexed_extensions` | Какие расширения файлов попадают в индекс |
| `include_extensionless_files` | Индексировать ли файлы без расширения |
| `query_word_match` | Искать документы со всеми словами или с любым |
| `max_response` | Сколько лучших ответов отдавать на один запрос |
| `ind_time` | Как часто в секундах делать полный проход по папкам |
| `scan_on_startup` | Делать ли полный проход сразу после старта |
| `server_mode` | Живой сервер (`active`) или замороженный архив (`archive`) |
| `document_catalog_storage` | Держать каталог путей в памяти или только в SQLite |
| `prm_base_dir` / `prd_base_dir` | Корни баз входящих (PRM) и исходящих (PRD). Пустая строка отключает источник |
| `prm_monthly_bases_dir` / `prd_monthly_bases_dir` | Где лежат помесячные базы `MM-ГОД.db3` |
| `opis_base_dir` | Каталог описи: файл `ГОД.db` / `ГОД.DB` |
| `f12_base_dir` | Каталог маршрутов F12: `ГОД.db` и общий `base.db` |
| `tlg_send_root` | Куда складывать телеграммы «к отправке» |
| `razn_output_dir` | Куда складывать файлы разноски |
| `hide_console_window` | Спрятать консоль при ручном запуске |
| `enable_prm_short_content_autodetect` | При появлении нового файла обновлять краткое содержание в базе PRM |

### Тонкие

| Поле | Зачем |
| --- | --- |
| `thread_count` | Размер пула потоков CPU. `0` — по числу ядер |
| `max_parallel_readers` | Сколько файлов читать с диска одновременно. `0` — без лимита |
| `file_indexing_timeout_sec` | Сколько секунд ждать индексацию одного файла |
| `compact_threshold_percent` | При каком проценте «дыр» в словаре сжимать индекс |
| `full_index_strategy` | Как собирать индекс с нуля: `batch` или `legacy` |
| `batch_reader_threads` | Потоки чтения в пакетной сборке |
| `batch_indexer_threads` | Потоки разбора текста в пакетной сборке. `0` — все логические CPU |
| `batch_queue_memory_mb` | Сколько мегабайт прочитанных данных держать в очереди |
| `sqlite_mirror_flush_interval_sec` | Как часто сбрасывать живые изменения индекса на диск |
| `sqlite_mirror_max_pending_ops` | При какой длине очереди сбросить изменения немедленно |
| `sqlite_load_threads` | Сколько соединений читать индекс при старте |
| `sqlite_precount_postings` | Считать ли заранее число вхождений, чтобы выделить память пачкой |

## 3. Рабочие настройки

### year

Строка года подставляется в имена файлов баз. Поле обязательное.

```json
"year": "2026"
```

- Помесячные базы AutoPad: `MM-2026.db3` (`01`…`13`).
- Опись: `opis_base_dir\2026.db` и `opis_base_dir\2026.DB`.
- F12: `f12_base_dir\2026.db`.
- В режиме `active`, если год совпадает с календарным и рядом лежит `ARCHIVE.db3`, эта база добавляется к списку.
- В режиме `archive` файл `ARCHIVE.db3` не используется.

Смена года не переносит файлы. Год выбирает базы, `index_roots` выбирает файлы на диске.

### asio_port

TCP-порт слушателя. Диапазон `1…65535`. Старое имя `port` ещё читается, в файл пишется `asio_port`. Если ключа нет, в коде подставляется `15001`, и файл перезаписывается.

```json
"asio_port": 15006
```

Порт задаётся один раз при старте. Занятый порт обрывает запуск. Клиент должен использовать тот же номер. Два экземпляра на одной машине — два порта и два каталога данных.

### index_roots

Абсолютные пути Windows, обход рекурсивный. Массив не может быть пустым. Существование папки при старте не проверяется. Старое имя — `dirs`.

```json
"index_roots": [
  "D:\\ЯНВАРЬ",
  "D:\\ФЕВРАЛЬ",
  "D:\\TLG"
]
```

В режиме `active` по этим корням идёт и слежение, и периодический проход. В режиме `archive` слежение и периодический проход выключены. Относительный путь сервер отвергает. В JSON обратный слэш пишется как `\\`.

### excluded_subtrees

Абсолютные пути, которые вырезаются из обхода, даже если лежат внутри корня. Пустой массив значит «исключений нет». Старое имя — `exclude_dirs`. Это поддерево, не маска файла.

```json
"index_roots": ["D:\\TLG"],
"excluded_subtrees": ["D:\\TLG\\OUT"]
```

### indexed_extensions и include_extensionless_files

Расширение пишется без точки. Нельзя пустую строку, пробелы по краям, точку, `*`, `?`, `/`, `\` и дубли, отличающиеся только регистром. Нужно хотя бы одно расширение или `include_extensionless_files: true`. Сравнение по последнему расширению имени, без учёта регистра.

Старый массив `extensions` ещё читается. Пустая строка в нём раньше означала файлы без расширения.

```json
"indexed_extensions": ["txt", "atl", "shp"],
"include_extensionless_files": true
```

Только тексты:

```json
"indexed_extensions": ["txt"],
"include_extensionless_files": false
```

Новое расширение попадает в индекс после перезапуска и ближайшего полного прохода или события слежения.

### query_word_match

| Значение | Поведение |
| --- | --- |
| `all` | Документ должен содержать каждое слово. Если одного слова нет в индексе, ответ пустой |
| `any` | Достаточно любого слова. Отсутствующие слова пропускаются |

Если ключа нет, действует `any`. Старый `exact_search: true` равен `all`, `false` равен `any`.

```json
"query_word_match": "all"
```

### max_response

Сколько лучших по релевантности ответов отдать. В коде по умолчанию `30`. В переносном примере службы стоит `50000`.

```json
"max_response": 50000
```

Ноль и отрицательное число дают лимит 0: пустой список, а не «без ограничения». Отдельного значения «все результаты» нет.

### ind_time и scan_on_startup

`ind_time` — период полного прохода в секундах, минимум 1. `1500` — это 25 минут. `scan_on_startup: true` запускает полный проход сразу после загрузки словаря. В коде по умолчанию старт со сканированием.

Оба поля работают только в режиме `active`. В `archive` таймер и стартовый проход не запускаются.

```json
"ind_time": 1500,
"scan_on_startup": false
```

Проход раз в час, не сразу после включения:

```json
"ind_time": 3600,
"scan_on_startup": false
```

### server_mode

| Значение | Что делает сервер |
| --- | --- |
| `active` | Следит за папками, обновляет индекс по таймеру, может использовать `ARCHIVE.db3` текущего года. Это режим по умолчанию |
| `archive` | Не следит, не сканирует при старте, не запускает периодическое обновление. Базы только помесячные. Ручное обновление индекса разрешено лишь локальной сессии с именем `admin` |

`archive` требует `document_catalog_storage` равным `sqlite`. Команда `--initial-update` разрешена только при `active`.

```json
"year": "2024",
"server_mode": "archive",
"document_catalog_storage": "sqlite"
```

### document_catalog_storage

Слой слов и вхождений всегда лежит в `inverted_index.sqlite`. Это поле выбирает только каталог документов: путь, время, размер, признак удаления.

| Значение | Где пути | Когда |
| --- | --- | --- |
| `memory` | В оперативной памяти. Значение по умолчанию, если ключа не было | Умеренный объём файлов |
| `sqlite` | В том же `inverted_index.sqlite`, без полной загрузки путей в RAM | Большой каталог или режим `archive` |

```json
"document_catalog_storage": "sqlite"
```

Путь к файлу базы индекса не настраивается.

### Пути к базам AutoPad

```json
"prm_base_dir": "D:\\BASES",
"prd_base_dir": "D:\\BASES_PRD",
"prm_monthly_bases_dir": "D:\\BASES\\METH_BASES",
"prd_monthly_bases_dir": "D:\\BASES_PRD\\METH_BASES"
```

- `prm_base_dir` — входящие. Обязательная строка. Пустая строка отключает источник, сервер стартует.
- `prd_base_dir` — исходящие. То же правило.
- Если ключа месячного каталога нет, сервер подставляет `корень\METH_BASES`.
- Имена файлов собираются сами: `01-2026.db3` … `13-2026.db3`. Отсутствующий месяц пропускается.
- В `active` рядом с корнем может использоваться `ARCHIVE.db3`. В `archive` он не открывается.

Выключить исходящие и положить месячные входящие на другой том:

```json
"prm_base_dir": "D:\\BASES",
"prm_monthly_bases_dir": "E:\\MONTHLY\\PRM",
"prd_base_dir": ""
```

Отсутствие ключа — ошибка формы. Пустая строка — штатный выключатель. Поиск по тексту файлов от этих путей не зависит.

### opis_base_dir и f12_base_dir

Это каталоги, не полные имена файлов. Год дописывает сервер.

```json
"opis_base_dir": "D:\\OPIS_ADMIN",
"f12_base_dir": "D:\\F12"
```

- Опись: `opis_base_dir\ГОД.db` и `opis_base_dir\ГОД.DB`.
- F12: всегда `f12_base_dir\ГОД.db`. Файл `f12_base_dir\base.db`, если есть, дополняет только текущий календарный год.
- Если ключей нет, подставляются `D:\OPIS_ADMIN` и `D:\F12`.

### tlg_send_root и razn_output_dir

Куда сервер пишет выгрузки. На индекс эти пути не влияют. Оба должны быть абсолютными, итоговый файл не может выйти за пределы каталога.

```json
"tlg_send_root": "D:\\",
"razn_output_dir": "D:\\OPIS_ADMIN\\РАЗНОСКА_ДЛЯ_ПРОСТАВЛЕНИЯ"
```

- Телеграммы к отправке: `tlg_send_root\МЕСЯЦ\ДАТА\...`. По умолчанию корень `D:\`.
- Разноска: каталог `razn_output_dir`. По умолчанию `D:\OPIS_ADMIN\РАЗНОСКА_ДЛЯ_ПРОСТАВЛЕНИЯ`.

Узкий корень отправки:

```json
"tlg_send_root": "D:\\TO_SEND"
```

### hide_console_window

Прячет консоль только у ручного запуска. Службу не трогает. Старое имя — `hide_mode`. По умолчанию `false`.

```json
"hide_console_window": false
```

Если консоль скрыта и настройки критически битые, окно показывается снова вместе с сообщением об ошибке.

### enable_prm_short_content_autodetect

При `true` событие «файл добавлен» в режиме `active` дополнительно обновляет опись и для входящих может записать краткое содержание в PRM. В коде по умолчанию `true`. В переносном примере службы стоит `false`.

Пропускаются пути с `OUT`, не-файлы, чужие расширения и выключенный источник PRM. В режиме `archive` наблюдателя нет, флаг ни на что не влияет.

```json
"server_mode": "active",
"enable_prm_short_content_autodetect": true,
"prm_base_dir": "D:\\BASES"
```

Это запись в базу, а не настройка поиска.

## 4. Сценарии «хочу, чтобы…»

После любого сценария — перезапуск. Остальной JSON не трогаем.

Подключить клиент: одно и то же число в `asio_port` и в клиенте. Второй экземпляр — другой порт и другой каталог данных.

Искать только нужные месяцы: править `index_roots`, не `year`. Лишнюю ветку вырезать через `excluded_subtrees`.

Открыть другой год баз:

```json
"year": "2025"
```

Заморозить прошлый год:

```json
"year": "2025",
"server_mode": "archive",
"document_catalog_storage": "sqlite"
```

Оставить только txt:

```json
"indexed_extensions": ["txt"],
"include_extensionless_files": false
```

Только файлы без расширения:

```json
"indexed_extensions": [],
"include_extensionless_files": true
```

Узкая короткая выдача:

```json
"query_word_match": "all",
"max_response": 100
```

Базы на другом диске, исходящие выключены:

```json
"prm_base_dir": "D:\\BASES",
"prm_monthly_bases_dir": "E:\\MONTHLY\\PRM",
"prd_base_dir": "",
"opis_base_dir": "E:\\OPIS",
"f12_base_dir": "E:\\F12"
```

Не сканировать в момент включения, первый полный проход через 30 минут. Слежение в режиме `active` остаётся:

```json
"scan_on_startup": false,
"ind_time": 1800
```

## 5. Тонкая настройка

Формула для зрителя: рабочий сервер этими полями не настраивают. Их открывают при конкретной жалобе на диск, старт, один зависший файл или первую сборку.

### thread_count

Размер CPU-пула. `0` — по числу логических процессоров. `2` и больше — явный размер. `1` и отрицательные запрещены. Если ключа нет, подставляется `6`.

Сетевые потоки этим полем не задаются: приём на двух потоках, планировщик и запись индекса — на одном каждый. Размер пула после старта не меняется.

```json
"thread_count": 0
```

### max_parallel_readers

Сколько файлов читать одновременно. `0` — без лимита. Ориентир: HDD — 1, SATA SSD — 2…4, NVMe — 4…8.

```json
"max_parallel_readers": 1
```

Это про диск. Ядрами заведует `thread_count`.

### file_indexing_timeout_sec

Секунды ожидания одного файла на полном обновлении. Диапазон 10…600. Если ключа нет, подставляется 60. В переносном примере стоит 120.

Если future файла не готова вовремя, путь пишется в журнал, цикл идёт дальше. Проход целиком не останавливается.

```json
"file_indexing_timeout_sec": 120
```

### compact_threshold_percent

После полного шага обновления считается доля пустых ячеек словаря. Если она меньше порога или дыр нет, сжатие пропускается. По умолчанию 5. Это уплотнение внутреннего словаря, не чистка баз и не удаление файлов.

```json
"compact_threshold_percent": 5.0
```

### full_index_strategy и batch

Конвейер используется при `batch` и пустом индексе. Если индекс уже не пуст, даже `batch` идёт обычным пошаговым обновлением. `legacy` всегда пошаговый. В коде по умолчанию `batch`.

| Поле | Диапазон | По умолчанию |
| --- | --- | --- |
| `batch_reader_threads` | 1…64 | 1 |
| `batch_indexer_threads` | 0 или 1…256. Ноль — все логические CPU | 0 |
| `batch_queue_memory_mb` | 16…2048 | 256 |

При `legacy` поля `batch_*` на сборку не влияют, но диапазон при старте всё равно проверяется.

```json
"full_index_strategy": "batch",
"batch_reader_threads": 1,
"batch_indexer_threads": 0,
"batch_queue_memory_mb": 256
```

### Зеркало SQLite и загрузка при старте

Эти поля не выбирают файл базы и не переключают каталог `memory` / `sqlite`.

| Поле | Смысл | Обычное |
| --- | --- | --- |
| `sqlite_mirror_flush_interval_sec` | Интервал сброса очереди, секунды. 0 и меньше внутри подменяются на 2 | `2.0` |
| `sqlite_mirror_max_pending_ops` | Сброс сразу, если очередь длиннее. `0` — только по таймеру | `500` |
| `sqlite_load_threads` | Соединения при чтении базы на старте. `1` — по очереди | `4` |
| `sqlite_precount_postings` | Перед загрузкой вхождений сделать `COUNT(*)` и заранее выделить массивы | `false` |

Чаще писать на диск:

```json
"sqlite_mirror_flush_interval_sec": 1.0,
"sqlite_mirror_max_pending_ops": 100
```

Предварительный подсчёт сам стоит прохода по таблице. Его включают после замера, не «для скорости» заранее.

## 6. Если сервер не поднялся

| Условие | Что исправить |
| --- | --- |
| Нет файла или JSON сломан | Вернуть читаемый `Settings.json` |
| Пустой `year` | Непустая строка года |
| Пустой или не абсолютный `index_roots` | Хотя бы один путь вида `D:\ПАПКА` |
| Не абсолютный путь в `excluded_subtrees` | Полные пути или пустой массив |
| Плохие расширения и нет файлов без расширения | Токены без точки, хотя бы один тип |
| `ind_time` меньше 1 | Секунды, минимум 1 |
| `thread_count` равен 1 или меньше нуля | `0` либо число от 2 |
| Порт вне 1…65535 или занят | Свободный порт |
| `archive` без каталога `sqlite` | `document_catalog_storage: sqlite` |
| Таймаут файла вне 10…600 | Вернуть в диапазон |
| Поля batch вне диапазона | Читатели 1…64, индексаторы 0 или 1…256, очередь 16…2048 |
| `query_word_match` не `all` и не `any` | Одно из двух слов |
| `server_mode` не `active` и не `archive` | Одно из двух слов |

Пустая строка `prm_base_dir` или `prd_base_dir` источник выключает. Отсутствующий ключ — ошибка формы. Журнал старта: `data-dir\logs`.

Рабочие поля отвечают на вопросы «где искать, какой год, какой порт, какие файлы, сколько ответов». Тонкие отвечают на вопрос «как быстро и какой ценой для диска и памяти».

## 7. Шпаргалка ведущего

1. Открыть `data-dir\Settings.json`. Каталог данных — не поле внутри файла.
2. Индекс всегда `inverted_index.sqlite` рядом. «Как хранить» — это `document_catalog_storage`.
3. Год, порт, корни, исключения, расширения.
4. Демо: `all` против `any` и укороченный `max_response`.
5. Пути баз: PRM, PRD, месячные каталоги, опись, F12. Пустая строка выключает PRM или PRD.
6. Куда пишутся отправка и разноска.
7. `active` / `archive` и обязательный SQLite-каталог для архива.
8. `ind_time` в секундах и флаг стартового прохода.
9. Тонкие поля пролистать по таблице и остановиться на `max_parallel_readers: 1` для жёсткого диска.
10. Сохранили — перезапустили. Незнакомые ключи не вырезать.
