## Реализация

Сервер читает `config.authentication_mode`: `required` по умолчанию (также при отсутствии поля) либо явно `none`. Неизвестное значение отклоняется. В `none` не открываются auth_clients.sqlite и ключ проверки; существующие файлы остаются на месте. Режим фиксируется при старте экземпляра и применяется после перезапуска.

Анонимная сессия не получает `authenticated_=true` и не становится admin. Её серверное имя всегда `unauthenticated_user`; IP берётся из TCP remote_endpoint. Старые USER_REGISTRY/AUTHENTICATE_V1 поддержаны в открытом режиме как совместимый ответ без назначения переданного имени и административных прав. В архиве обслуживание без токена допускается только для точного IPv4 peer 127.0.0.1.

Negotiation сохраняет версию 1 и payload 8 байт. Новый бит `CAPABILITY_ANONYMOUS_ACCESS_V1=1u<<2` согласован в обоих репозиториях. Команды и ErrorCode не перенумерованы. PersonalRequest не расширялся: IP добавлен в отдельный серверный элемент очереди и столбец `logs.remote_ip`. Миграция добавляет столбец без удаления старых строк. Журналируются также отказы команд.

В клиенте добавлен явный пункт «Без авторизации», автоматически доступный при отсутствии токена и admin. Это состояние готовности местного интерфейса, не подтверждение личности на сервере. Таймер выхода не проверяет носитель для этого режима. На каждом соединении клиент заново читает capabilities; открытый сервер обслуживается без отправки токена. Без выбранных учётных данных защищённый/старый сервер пропускается с понятной ошибкой. При выбранном токене смешанная группа сохраняет доступ к открытым источникам даже при отказе подписи на защищённом. Legacy имена API `isServerAuthorized`/`authorizedServerCount` учитывают также явно объявленный анонимный доступ, при этом отдельное состояние подтверждённой личности не подделывается.

Установщик и конфигуратор предлагают режим. Local-Machine-Install в `none` пропускает provision ключей и токена, сохраняя первоначальную индексацию. CLI конфигуратора поддерживает `--authentication-mode required|none`, inspect показывает значение. Обновление сохраняет режим из импортированных настроек.

Для полной пересборки клиента канонический entrypoint поддерживает `tools/release.bat -Rebuild`; bump, упаковка и публикация остаются единым workflow.

## Именные рабочие операции

- Загрузка на отправку использует общее имя в папке оператора. TCP-проверка подтвердила конечный путь и содержимое; загрузка разноски также проверена.
- GET_ATTACHMENTS в открытом режиме принудительно использует карту `unauthenticated_user`. Переданное клиентом имя admin не выбирает чужую папку. Общий одноразовый буфер включается только явной настройкой prefix_map.
- Известное удаление исходного одноразового буфера до доставки ответа сохранено; оно не относится к обычным приложениям карточек. Историческая находка аудитов 10–11 октября не закрывалась этим изменением.
- Общий IP не устанавливает личность человека; открытый экземпляр обслуживает все компьютеры, допущенные сетью к его порту.

При проектировании записи события использована [рекомендация OWASP по журналированию](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html): источник, идентичность при её наличии, действие и время фиксируются отдельно. Выбор явного режима и сохранение отказа по умолчанию — решение для совместимости существующих установок; открытый режим не включается вследствие ошибки авторизации.
