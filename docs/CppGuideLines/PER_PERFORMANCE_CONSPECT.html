Per: Производительность - Подробный конспект

О разделе: Раздел Per содержит рекомендации по оптимизации производительности. Помните: преждевременная оптимизация - корень всех зол. Оптимизируйте только после измерения и только то, что действительно нужно.

Per.1: Не оптимизируйте без причины

❌ Как НЕ надо

// Плохо: оптимизация без измерения
void process_data(std::vector<int>& data) {
    // "Оптимизация": ручной цикл вместо алгоритма
    for (size_t i = 0; i < data.size(); ++i) {
        data[i] = data[i] * 2;  // "быстрее"?
    }
    // Код сложнее, но реально ли быстрее?
}

✅ Как надо

// Хорошо: простой и понятный код
#include <algorithm>
void process_data(std::vector<int>& data) {
    std::transform(data.begin(), data.end(), data.begin(),
                   [](int x) { return x * 2; });
    // Просто, понятно, возможно уже оптимизировано компилятором
}

// Если нужно оптимизировать - сначала измерьте:
#include <chrono>
void benchmark() {
    auto start = std::chrono::high_resolution_clock::now();
    process_data(data);
    auto end = std::chrono::high_resolution_clock::now();
    // измерьте время выполнения
}

Per.2: Не оптимизируйте преждевременно

Важно: Преждевременная оптимизация делает код сложнее без гарантии улучшения производительности. Сначала сделайте код правильным и понятным, затем измерьте производительность и оптимизируйте только узкие места.

❌ Как НЕ надо

// Плохо: преждевременная оптимизация
class DataProcessor {
    int* cache;  // ручное управление памятью
    size_t cache_size;
public:
    DataProcessor() : cache(nullptr), cache_size(0) {}
    ~DataProcessor() { delete[] cache; }
    // Сложный код для "оптимизации", который может быть не нужен
};

✅ Как надо

// Хорошо: простой код сначала
class DataProcessor {
    std::vector<int> cache;  // просто и безопасно
public:
    // Простой код, легко понять и поддерживать
    // Оптимизируйте только если измерения покажут необходимость
};

Per.6: Не делайте заявлений о производительности без измерений

Правило: Измеряйте, не угадывайте. Современные компиляторы и процессоры могут делать неожиданные оптимизации.

❌ Как НЕ надо

// Плохо: предположения без измерений
void process() {
    // "Этот код быстрее, потому что..."
    // Но реально ли быстрее? Неизвестно без измерений!
    for (int i = 0; i < 1000; ++i) {
        // сложная оптимизация
    }
}

✅ Как надо

// Хорошо: измерение производительности
#include <chrono>
#include <iostream>

void benchmark() {
    const int iterations = 1000000;
    
    auto start = std::chrono::high_resolution_clock::now();
    for (int i = 0; i < iterations; ++i) {
        process_variant1();
    }
    auto end = std::chrono::high_resolution_clock::now();
    auto duration1 = std::chrono::duration_cast<std::chrono::microseconds>
                     (end - start).count();
    
    start = std::chrono::high_resolution_clock::now();
    for (int i = 0; i < iterations; ++i) {
        process_variant2();
    }
    end = std::chrono::high_resolution_clock::now();
    auto duration2 = std::chrono::duration_cast<std::chrono::microseconds>
                     (end - start).count();
    
    std::cout << "Variant 1: " << duration1 << " microseconds\n";
    std::cout << "Variant 2: " << duration2 << " microseconds\n";
}

Per.11: Переместите вычисления из времени выполнения в время компиляции

Проблема/Контекст

Вычисления на этапе компиляции не требуют времени выполнения и могут быть использованы в контекстах, требующих констант времени компиляции (например, размеры массивов, шаблоны).

❌ Как НЕ надо

// Плохо: вычисление во время выполнения
double square(double d) { return d * d; }
static double s2 = square(2);  // вычисляется во время выполнения

int factorial(int n) {
    if (n <= 1) return 1;
    return n * factorial(n - 1);
}
int fact_5 = factorial(5);  // вычисляется во время выполнения

✅ Как надо

// Хорошо: вычисление на этапе компиляции
constexpr double square(double d) { return d * d; }
constexpr double s2 = square(2);  // вычисляется на этапе компиляции

constexpr int factorial(int n) {
    return (n <= 1) ? 1 : n * factorial(n - 1);
}
constexpr int fact_5 = factorial(5);  // вычисляется на этапе компиляции

// Можно использовать в константах времени компиляции:
std::array<int, fact_5> arr;  // размер массива известен на этапе компиляции

Заключение

Ключевые принципы раздела Per (Производительность):

  • Не оптимизируйте без причины: Оптимизация должна быть обоснована
  • Не оптимизируйте преждевременно: Сначала сделайте код правильным
  • Измеряйте: Не делайте предположений о производительности
  • constexpr: Используйте вычисления на этапе компиляции
  • Профилирование: Используйте профилировщики для поиска узких мест
Правило: "Преждевременная оптимизация - корень всех зол" (Donald Knuth). Сначала сделайте код правильным и понятным, затем измерьте производительность и оптимизируйте только то, что действительно нужно.
