CP: Параллелизм - Подробный конспект

О разделе: Раздел CP содержит рекомендации по написанию многопоточного кода. Правильное использование синхронизации предотвращает гонки данных и делает код безопасным для параллельного выполнения.

CP.1: Предполагайте, что ваш код будет выполняться как часть многопоточной программы

❌ Как НЕ надо

// Плохо: статические переменные вызывают гонки данных
double cached_computation(int x) {
    static int cached_x = 0;
    static double cached_result = 0.0;
    
    if (cached_x != x) {
        cached_x = x;
        cached_result = expensive_computation(x);
    }
    return cached_result;  // гонка данных при многопоточном доступе!
}

✅ Как надо

// Хорошо: потокобезопасный кэш
#include <mutex>
#include <unordered_map>

class ThreadSafeCache {
    std::mutex mtx;
    std::unordered_map<int, double> cache;
public:
    double get(int x) {
        std::lock_guard<std::mutex> lock(mtx);
        auto it = cache.find(x);
        if (it != cache.end()) {
            return it->second;
        }
        double result = expensive_computation(x);
        cache[x] = result;
        return result;
    }
};

CP.2: Избегайте гонок данных

Важно: Гонка данных возникает, когда два потока обращаются к одному объекту одновременно, и хотя бы один из них выполняет запись. Это приводит к неопределённому поведению.

❌ Как НЕ надо

// Плохо: гонка данных
int counter = 0;

void increment() {
    ++counter;  // гонка данных! Не атомарная операция
}

// В многопоточной программе:
std::thread t1(increment);
std::thread t2(increment);
// counter может быть любым значением!

✅ Как надо

// Хорошо: атомарные операции
#include <atomic>

std::atomic<int> counter{0};

void increment() {
    ++counter;  // атомарная операция, безопасно
}

// Или используйте мьютекс:
#include <mutex>
int counter = 0;
std::mutex mtx;

void increment() {
    std::lock_guard<std::mutex> lock(mtx);
    ++counter;  // защищено мьютексом
}

CP.20: Используйте RAII, никогда не используйте простые lock()/unlock()

❌ Как НЕ надо

// Плохо: ручное управление блокировкой
std::mutex mtx;

void critical_section() {
    mtx.lock();
    // ... работа ...
    if (error) {
        return;  // блокировка не снята!
    }
    mtx.unlock();  // легко забыть
}

✅ Как надо

// Хорошо: RAII для блокировок
#include <mutex>

std::mutex mtx;

void critical_section() {
    std::lock_guard<std::mutex> lock(mtx);
    // ... работа ...
    if (error) {
        return;  // блокировка автоматически снимется
    }
    // блокировка автоматически снимется при выходе
}

CP.21: Используйте std::lock() или std::scoped_lock для захвата нескольких mutex

❌ Как НЕ надо

// Плохо: возможна взаимоблокировка
std::mutex mtx1, mtx2;

void thread1() {
    std::lock_guard<std::mutex> lock1(mtx1);
    std::lock_guard<std::mutex> lock2(mtx2);  // может заблокироваться
}

void thread2() {
    std::lock_guard<std::mutex> lock2(mtx2);
    std::lock_guard<std::mutex> lock1(mtx1);  // взаимоблокировка!
}

✅ Как надо

// Хорошо: std::scoped_lock (C++17)
#include <mutex>

std::mutex mtx1, mtx2;

void thread1() {
    std::scoped_lock lock(mtx1, mtx2);  // безопасный захват обоих
    // ...
}

void thread2() {
    std::scoped_lock lock(mtx1, mtx2);  // безопасный захват обоих
    // ...
}

// Или std::lock для C++11/14:
void thread1_old() {
    std::lock(mtx1, mtx2);
    std::lock_guard<std::mutex> lock1(mtx1, std::adopt_lock);
    std::lock_guard<std::mutex> lock2(mtx2, std::adopt_lock);
    // ...
}

Заключение

Ключевые принципы раздела CP (Параллелизм):

  • Предполагайте многопоточность: Пишите код, безопасный для параллельного выполнения
  • Избегайте гонок данных: Используйте синхронизацию для защиты общих данных
  • RAII для блокировок: Используйте lock_guard и scoped_lock
  • Атомарные операции: Используйте std::atomic для простых операций
  • Избегайте взаимоблокировок: Используйте std::lock для множественных мьютексов

Конспект создан на основе C++ Core Guidelines. Полный документ: https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines
