Blockchain Transaction Indexer — Решение и Объяснение

0. Зачем это нужно? Какие проблемы решает?

Реальная проблема блокчейн-нод

Блокчейн-ноды (Ethereum, Bitcoin и др.) предоставляют JSON-RPC API для доступа к данным, но у них есть серьёзные ограничения для практического использования:

Проблема 1: Невозможность поиска по адресу

Что происходит: Блокчейн-нода может ответить на вопрос "Дай мне блок номер 1000000" или "Дай мне транзакцию с хешем 0xabc...", но она не может ответить на вопрос "Покажи все транзакции адреса 0x742d35cc6634c0532925a3b844bc9e7595f0beb".

Почему так? Блокчейн хранит данные в виде цепочки блоков, где каждый блок содержит список транзакций. Но транзакции не индексированы по адресам отправителя/получателя. Чтобы найти все транзакции адреса, нужно перебрать все блоки от начала блокчейна (более 20 миллионов блоков в Ethereum на 2024 год). 
# Что МОЖЕТ нода:
curl -X POST http://localhost:8545 -d '{
  "jsonrpc": "2.0",
  "method": "eth_getBlockByNumber",
  "params": ["0x1000000", true],
  "id": 1
}'
# ✅ Вернёт блок номер 1000000

# Что НЕ МОЖЕТ нода:
curl -X POST http://localhost:8545 -d '{
  "jsonrpc": "2.0",
  "method": "eth_getTransactionsByAddress",  # ❌ Такого метода нет!
  "params": ["0x742d35cc6634c0532925a3b844bc9e7595f0beb"],
  "id": 1
}'
# ❌ Метод не существует

Проблема 2: Медленные запросы

Даже если бы можно было искать по адресу, это требовало бы:

  • Сканирование миллионов блоков — каждый запрос занимал бы минуты или часы
  • Нагрузка на ноду — каждый запрос заставлял бы ноду делать тяжёлую работу
  • Невозможность масштабирования — при 1000 одновременных запросов нода упадёт

Проблема 3: Нет удобного API для аналитики

Для построения дашбордов, аналитики, отчётов нужны запросы типа:

  • "Покажи транзакции адреса X за последний месяц"
  • "Найди все транзакции в диапазоне блоков 1000000-1000100"
  • "Посчитай сумму всех входящих транзакций для адреса Y"
  • "Покажи топ-10 адресов по объёму транзакций"

Блокчейн-нода не предоставляет таких возможностей — это не её задача. Её задача — хранить и валидировать блоки, а не делать аналитику.

Кто и зачем использует Transaction Indexer?

1. Блокчейн-эксплореры (Blockchain Explorers)

Примеры: Etherscan.io, Blockchain.com, BscScan.com

Что они делают: Показывают пользователям историю транзакций, балансы адресов, статистику сети. Когда вы заходите на Etherscan и вводите адрес кошелька, вы видите все его транзакции — это работает благодаря индексатору транзакций.

Без индексера: Каждый запрос пользователя требовал бы сканирования 20+ миллионов блоков. Это невозможно в реальном времени.
С индексером: Запрос выполняется за миллисекунды через SQL запрос к индексированной БД.

2. Криптовалютные биржи

Что им нужно:

  • Отслеживать входящие депозиты пользователей
  • Проверять подтверждения транзакций
  • Строить отчёты по транзакциям
  • Обнаруживать подозрительную активность

Биржа не может каждый раз сканировать весь блокчейн — нужна быстрая БД с индексами.

3. Аналитические платформы

Примеры: Dune Analytics, Nansen, Glassnode

Эти сервисы строят графики, анализируют паттерны, делают прогнозы. Им нужен быстрый доступ к историческим данным с фильтрацией и агрегацией — именно то, что предоставляет индексер.

4. DeFi приложения

Децентрализованные финансовые приложения часто показывают пользователям:

  • Историю их операций
  • Статистику по пулам ликвидности
  • Аналитику по токенам

Всё это требует быстрого поиска транзакций по различным критериям.

5. Комплаенс и AML (Anti-Money Laundering)

Финансовые регуляторы требуют отслеживания транзакций для предотвращения отмывания денег. Нужно быстро находить все транзакции связанные с подозрительными адресами — это невозможно без индексации.

Технические преимущества индексера

Сравнение: Прямой запрос к ноде vs Индексер

Задача Прямой запрос к ноде С индексером
Найти все транзакции адреса ❌ Невозможно (нет такого метода) ✅ SQL запрос за <100ms
Транзакции в диапазоне блоков ⚠️ Нужно делать N запросов (по одному на блок) ✅ Один SQL запрос с WHERE block_number BETWEEN
Агрегация (сумма, количество) ❌ Нужно получить все данные и считать в коде ✅ SQL SUM/COUNT за миллисекунды

Экономические преимущества

Стоимость запросов

  • Прямой запрос к ноде: Каждый запрос нагружает ноду. Если у вас публичная нода (Infura, Alchemy), вы платите за каждый запрос. 1000 запросов в секунду = огромные расходы.
  • С индексером: Вы делаете один запрос к ноде при синхронизации блока (раз в 12 секунд для Ethereum). Все остальные запросы идут к вашей локальной БД — бесплатно.

Независимость

Если публичная нода (Infura/Alchemy) недоступна или ограничивает вас, ваш сервис продолжает работать, используя уже проиндексированные данные. Вы не зависите от внешних сервисов для поиска транзакций.

Практический пример использования

Сценарий: Вы создаёте криптовалютный кошелёк-приложение для пользователей.

Без индексера:

  1. Пользователь открывает приложение и хочет увидеть историю транзакций
  2. Приложение пытается получить все транзакции через RPC
  3. Нода не может найти транзакции по адресу напрямую
  4. Придётся сканировать все блоки (невозможно)
  5. ❌ Пользователь ждёт вечность или видит ошибку

С индексером:

  1. Индексер работает в фоне, постоянно синхронизируясь с блокчейном
  2. Все транзакции сохраняются в БД с индексами
  3. Пользователь открывает приложение
  4. Приложение делает запрос: GET /transactions?address=0x742d...
  5. Индексер возвращает результат за 50ms из БД
  6. ✅ Пользователь видит историю транзакций мгновенно
Итог: Transaction Indexer — это необходимый слой между блокчейн-нодой и приложениями, который делает данные блокчейна доступными для практического использования. Без него невозможно построить большинство реальных приложений на блокчейне.

1. Что требуется в задании?

Общая задача

Нужно создать бэкенд-сервис, который:

  1. Подключается к блокчейн ноде через JSON-RPC
  2. Периодически получает новые блоки
  3. Извлекает транзакции из блоков
  4. Сохраняет транзакции в базу данных
  5. Предоставляет HTTP API для поиска транзакций

Проблема/Контекст

Блокчейн ноды предоставляют данные через JSON-RPC API, но для быстрого поиска транзакций по адресам или диапазонам блоков нужна собственная индексация. Прямые запросы к ноде медленные и неудобные для аналитики. Решение — создать промежуточный сервис, который постоянно синхронизируется с блокчейном и предоставляет быстрый API для запросов.

Решение

Создаём асинхронный сервис на C++ с использованием Boost.Asio для неблокирующих операций, который работает в фоновом режиме, обрабатывает блоки параллельно и предоставляет REST API.

2. Архитектура решения

Компоненты системы

┌─────────────────────────────────────────────────────────────┐ │ RPC Client (JSON-RPC клиент) │ │ - Подключение к блокчейн ноде │ │ - Вызовы eth_blockNumber, eth_getBlockByNumber │ │ - Обработка ошибок и повторные попытки │ └─────────────────────────────────────────────────────────────┘ │ ▼ ┌─────────────────────────────────────────────────────────────┐ │ Block Fetcher (Получение блоков) │ │ - Периодический опрос ноды (polling) │ │ - Отслеживание последнего обработанного блока │ │ - Очередь блоков для обработки │ └─────────────────────────────────────────────────────────────┘ │ ▼ ┌─────────────────────────────────────────────────────────────┐ │ Transaction Parser (Парсинг транзакций) │ │ - Извлечение данных из JSON блока │ │ - Валидация полей транзакций │ │ - Подготовка данных для сохранения │ └─────────────────────────────────────────────────────────────┘ │ ▼ ┌─────────────────────────────────────────────────────────────┐ │ Storage Layer (База данных) │ │ - SQLite/PostgreSQL │ │ - Индексы по address, block_number │ │ - Защита от дубликатов (UNIQUE constraint) │ └─────────────────────────────────────────────────────────────┘ │ ▼ ┌─────────────────────────────────────────────────────────────┐ │ HTTP Server (REST API) │ │ - GET /transactions с фильтрами │ │ - Пагинация через cursor │ │ - JSON ответы │ └─────────────────────────────────────────────────────────────┘

Поток данных

  1. RPC Client периодически вызывает eth_blockNumber
  2. Если есть новые блоки, Block Fetcher получает их через eth_getBlockByNumber
  3. Transaction Parser извлекает транзакции из JSON
  4. Storage Layer сохраняет транзакции в БД (с проверкой дубликатов)
  5. HTTP Server обрабатывает запросы пользователей и возвращает данные из БД
Важно: Все компоненты работают асинхронно через Boost.Asio, что позволяет обрабатывать множество операций параллельно без блокировки потоков.

3. Детальное объяснение компонентов

3.1. RPC Client

Проблема/Контекст

Нужно общаться с блокчейн нодой через JSON-RPC протокол. Это HTTP POST запросы с JSON телом, содержащим метод и параметры. Например, для получения номера последнего блока нужно отправить: 

{
  "jsonrpc": "2.0",
  "method": "eth_blockNumber",
  "params": [],
  "id": 1
}

Ответ будет содержать номер блока в hex формате: "0x1234abc"

Решение

Создаём класс RpcClient, который использует Boost.Beast для HTTP запросов и nlohmann/json для работы с JSON.

Разбор синтаксиса

#include <boost/asio.hpp>
#include <boost/beast.hpp>
#include <nlohmann/json.hpp>
#include <string>
#include <optional>

namespace beast = boost::beast;
namespace http = beast::http;
namespace net = boost::asio;
using tcp = boost::asio::ip::tcp;
using json = nlohmann::json;

class RpcClient {
public:
    RpcClient(
        net::io_context& io,           // контекст для асинхронных операций
        const std::string& host,        // адрес ноды (например, "localhost")
        const std::string& port,        // порт (например, "8545")
        const std::string& endpoint      // путь (например, "/")
    );
    
    // Асинхронный вызов RPC метода
    boost::asio::awaitable<std::optional<json>> call(
        const std::string& method,      // имя метода ("eth_blockNumber")
        const json& params = json::array()  // параметры метода
    );
    
private:
    net::io_context& io_;
    std::string host_;
    std::string port_;
    std::string endpoint_;
    uint64_t request_id_{1};           // счётчик для id запросов
};
  • boost::asio::awaitable — возвращаемый тип корутины (C++20), позволяет использовать co_await
  • std::optional<json> — результат может отсутствовать при ошибке
  • request_id_ — уникальный ID для каждого запроса (требуется JSON-RPC)

Как это работает?

boost::asio::awaitable<std::optional<json>> 
RpcClient::call(const std::string& method, const json& params) {
    // 1. Создаём JSON-RPC запрос
    json request = {
        {"jsonrpc", "2.0"},
        {"method", method},
        {"params", params},
        {"id", request_id_++}
    };
    
    // 2. Подключаемся к серверу
    tcp::resolver resolver(io_);
    auto endpoints = co_await resolver.async_resolve(host_, port_);
    
    beast::tcp_stream stream(io_);
    co_await stream.async_connect(endpoints);
    
    // 3. Отправляем HTTP POST запрос
    http::request<http::string_body> req{http::verb::post, endpoint_, 11};
    req.set(http::field::host, host_);
    req.set(http::field::content_type, "application/json");
    req.body() = request.dump();
    req.prepare_payload();
    
    co_await http::async_write(stream, req);
    
    // 4. Читаем ответ
    beast::flat_buffer buffer;
    http::response<http::string_body> res;
    co_await http::async_read(stream, buffer, res);
    
    // 5. Парсим JSON ответ
    json response = json::parse(res.body());
    
    // 6. Проверяем наличие ошибки
    if (response.contains("error")) {
        co_return std::nullopt;  // ошибка RPC
    }
    
    // 7. Возвращаем результат
    co_return response["result"];
}

Пошаговое объяснение:

  1. Формируем JSON-RPC запрос с методом и параметрами
  2. Разрешаем DNS имя хоста в IP адреса
  3. Устанавливаем TCP соединение
  4. Отправляем HTTP POST с JSON телом
  5. Читаем HTTP ответ
  6. Парсим JSON и проверяем наличие ошибок
  7. Возвращаем результат через co_return
Ключевой момент: Использование co_await делает код неблокирующим — пока ждём ответа от сервера, поток может обрабатывать другие задачи.

Дополнительные примеры

// Получение номера последнего блока

if (block_number_json) {
    std::string hex = *block_number_json;
    uint64_t block_number = std::stoull(hex, nullptr, 16);  // конвертация hex → число
}

// Получение блока по номеру
json params = {"0x" + std::to_string(block_number), true};  // true = полные транзакции

    // block_json содержит все данные блока, включая транзакции
}

3.2. Block Fetcher

Проблема/Контекст

Нужно постоянно отслеживать новые блоки в блокчейне. Блоки появляются периодически (в Ethereum примерно каждые 12 секунд). После перезапуска сервиса нужно продолжить с последнего обработанного блока, а не начинать с начала.

Решение

Создаём класс BlockFetcher, который:

  • Хранит номер последнего обработанного блока
  • Периодически опрашивает ноду (polling)
  • Помещает новые блоки в очередь для обработки
  • Восстанавливает состояние из БД при старте

Разбор синтаксиса

#include <boost/asio.hpp>
#include <boost/asio/experimental/channel.hpp>
#include <atomic>
#include <memory>

class BlockFetcher {
public:
    BlockFetcher(
        net::io_context& io,
        RpcClient& rpc_client,
        Storage& storage,
        std::size_t poll_interval_ms = 2000  // опрос каждые 2 секунды
    );
    
    // Запуск фонового процесса получения блоков
    void start();
    
    // Остановка (graceful shutdown)
    void stop();
    
    // Канал для передачи блоков в обработчик
    using BlockChannel = boost::asio::experimental::channel<
        void(boost::system::error_code, json)
    >;
    
    BlockChannel& getBlockChannel() { return block_channel_; }
    
private:
    // Основной цикл опроса
    boost::asio::awaitable<void> fetchLoop();
    
    // Получение одного блока
    boost::asio::awaitable<bool> fetchBlock(uint64_t block_number);
    
    net::io_context& io_;
    RpcClient& rpc_client_;
    Storage& storage_;
    std::atomic<uint64_t> last_processed_block_{0};
    std::atomic<bool> running_{false};
    BlockChannel block_channel_;
    std::chrono::milliseconds poll_interval_;
};
  • boost::asio::experimental::channel — потокобезопасная очередь для передачи данных между корутинами
  • std::atomic<uint64_t> — атомарная переменная для безопасного доступа из разных потоков
  • poll_interval_ms — интервал между опросами ноды

Как это работает?

void BlockFetcher::start() {
    // 1. Восстанавливаем последний обработанный блок из БД
    last_processed_block_ = storage_.getLastProcessedBlock();
    
    running_ = true;
    
    // 2. Запускаем корутину fetchLoop
    boost::asio::co_spawn(
        io_,
        [this]() { return fetchLoop(); },
        boost::asio::detached
    );
}

boost::asio::awaitable<void> BlockFetcher::fetchLoop() {
    while (running_) {
        try {
            // 1. Получаем номер последнего блока в сети
            auto latest_json = co_await rpc_client_.call("eth_blockNumber");
            if (!latest_json) {
                co_await net::steady_timer(io_, poll_interval_).async_wait();
                continue;  // ошибка RPC, повторяем через интервал
            }
            
            // 2. Конвертируем hex в число
            std::string hex = *latest_json;
            uint64_t latest_block = std::stoull(hex, nullptr, 16);
            
            // 3. Обрабатываем все новые блоки
            uint64_t current = last_processed_block_.load() + 1;
            while (current <= latest_block && running_) {
                auto success = co_await fetchBlock(current);
                if (success) {
                    last_processed_block_.store(current);
                    current++;
                } else {
                    // Ошибка получения блока, ждём перед повтором
                    co_await net::steady_timer(io_, poll_interval_).async_wait();
                    break;
                }
            }
            
            // 4. Ждём перед следующим опросом
            co_await net::steady_timer(io_, poll_interval_).async_wait();
            
        } catch (const std::exception& e) {
            // Логируем ошибку и продолжаем
            std::cerr << "Error in fetchLoop: " << e.what() << std::endl;
            co_await net::steady_timer(io_, poll_interval_).async_wait();
        }
    }
}

boost::asio::awaitable<bool> BlockFetcher::fetchBlock(uint64_t block_number) {
    // Формируем hex строку для номера блока
    std::stringstream ss;
    ss << "0x" << std::hex << block_number;
    
    json params = {ss.str(), true};  // true = полные транзакции
    
    auto block_json = co_await rpc_client_.call("eth_getBlockByNumber", params);
    if (!block_json) {
        co_return false;  // ошибка RPC
    }
    
    // Отправляем блок в канал для обработки
    boost::system::error_code ec;
    co_await block_channel_.async_send(ec, *block_json);
    
    co_return !ec;  // true если успешно отправлено
}
Преимущества: Использование канала позволяет разделить получение блоков и их обработку. Пока один блок обрабатывается, можно уже получать следующий.

3.3. Transaction Parser

Проблема/Контекст

Блокчейн нода возвращает блок в формате JSON с множеством полей. Нужно извлечь только транзакции и преобразовать их в структуру для сохранения в БД. Поля могут быть в hex формате (например, адреса, хеши, значения), их нужно конвертировать.

Решение

Создаём класс TransactionParser, который извлекает транзакции из JSON блока и преобразует их в структуру Transaction.

Разбор синтаксиса

#include <nlohmann/json.hpp>
#include <string>
#include <vector>
#include <cstdint>

struct Transaction {
    uint64_t block_number;
    std::string block_hash;
    std::string tx_hash;
    std::string from_address;
    std::string to_address;      // может быть пустым для создания контракта
    std::string value;            // в wei (hex строка)
    uint64_t timestamp;
};

class TransactionParser {
public:
    // Парсинг блока и извлечение транзакций
    static std::vector<Transaction> parseBlock(const json& block_json);
    
private:
    // Конвертация hex строки в число
    static uint64_t hexToUint64(const std::string& hex);
    
    // Нормализация адреса (убрать префикс 0x, привести к нижнему регистру)
    static std::string normalizeAddress(const std::string& addr);
};

Как это работает?

std::vector<Transaction> TransactionParser::parseBlock(const json& block_json) {
    std::vector<Transaction> transactions;
    
    // 1. Извлекаем основные поля блока
    std::string block_hash = block_json["hash"].get<std::string>();
    uint64_t block_number = hexToUint64(block_json["number"].get<std::string>());
    uint64_t timestamp = hexToUint64(block_json["timestamp"].get<std::string>());
    
    // 2. Проверяем наличие транзакций
    if (!block_json.contains("transactions") || !block_json["transactions"].is_array()) {
        return transactions;  // пустой блок
    }
    
    // 3. Обрабатываем каждую транзакцию
    for (const auto& tx_json : block_json["transactions"]) {
        Transaction tx;
        tx.block_number = block_number;
        tx.block_hash = normalizeAddress(block_hash);
        tx.tx_hash = normalizeAddress(tx_json["hash"].get<std::string>());
        tx.from_address = normalizeAddress(tx_json["from"].get<std::string>());
        
        // to может быть null для создания контракта
        if (tx_json.contains("to") && !tx_json["to"].is_null()) {
            tx.to_address = normalizeAddress(tx_json["to"].get<std::string>());
        } else {
            tx.to_address = "";  // создание контракта
        }
        
        tx.value = tx_json["value"].get<std::string>();  // оставляем hex для точности
        tx.timestamp = timestamp;
        
        transactions.push_back(tx);
    }
    
    return transactions;
}

uint64_t TransactionParser::hexToUint64(const std::string& hex) {
    // Убираем префикс 0x если есть
    std::string clean = hex;
    if (clean.size() > 2 && clean.substr(0, 2) == "0x") {
        clean = clean.substr(2);
    }
    
    // Конвертируем hex в число
    return std::stoull(clean, nullptr, 16);
}

std::string TransactionParser::normalizeAddress(const std::string& addr) {
    std::string result = addr;
    
    // Убираем префикс 0x
    if (result.size() > 2 && result.substr(0, 2) == "0x") {
        result = result.substr(2);
    }
    
    // Приводим к нижнему регистру (EIP-55 не учитываем для простоты)
    std::transform(result.begin(), result.end(), result.begin(), ::tolower);
    
    return result;
}
Важно: Значение транзакции храним как hex строку, чтобы сохранить точность (wei — это очень большие числа). При необходимости можно конвертировать в decimal для отображения.

3.4. Storage Layer

Проблема/Контекст

Нужно хранить транзакции в реляционной БД с возможностью быстрого поиска по адресу и диапазону блоков. Также важно избежать дубликатов при повторной обработке блоков (например, при перезапуске или обработке реоргов).

Решение

Используем SQLite (легковесная) или PostgreSQL (для продакшена). Создаём таблицу с индексами и UNIQUE constraint на tx_hash для защиты от дубликатов.

Разбор синтаксиса

#include <sqlite3.h>
#include <string>
#include <vector>
#include <mutex>

class Storage {
public:
    Storage(const std::string& db_path);
    ~Storage();
    
    // Инициализация схемы БД
    void initialize();
    
    // Сохранение транзакций (с проверкой дубликатов)
    bool insertTransactions(const std::vector<Transaction>& transactions);
    
    // Получение последнего обработанного блока
    uint64_t getLastProcessedBlock();
    
    // Обновление последнего обработанного блока
    void updateLastProcessedBlock(uint64_t block_number);
    
    // Поиск транзакций (для API)
    std::vector<Transaction> findTransactions(
        const std::optional<std::string>& address = std::nullopt,
        const std::optional<uint64_t>& from_block = std::nullopt,
        const std::optional<uint64_t>& to_block = std::nullopt,
        size_t limit = 100,
        const std::optional<std::string>& cursor = std::nullopt
    );
    
private:
    sqlite3* db_;
    std::mutex db_mutex_;  // защита от конкурентного доступа
};

Как это работает?

void Storage::initialize() {
    const char* sql = R"(
        CREATE TABLE IF NOT EXISTS transactions (
            id INTEGER PRIMARY KEY AUTOINCREMENT,
            block_number INTEGER NOT NULL,
            block_hash TEXT NOT NULL,
            tx_hash TEXT NOT NULL UNIQUE,  -- UNIQUE предотвращает дубликаты
            from_address TEXT NOT NULL,
            to_address TEXT,
            value TEXT NOT NULL,
            timestamp INTEGER NOT NULL
        );
        
        -- Индексы для быстрого поиска
        CREATE INDEX IF NOT EXISTS idx_block_number ON transactions(block_number);
        CREATE INDEX IF NOT EXISTS idx_from_address ON transactions(from_address);
        CREATE INDEX IF NOT EXISTS idx_to_address ON transactions(to_address);
        CREATE INDEX IF NOT EXISTS idx_timestamp ON transactions(timestamp);
        
        -- Составной индекс для поиска по адресу и блоку
        CREATE INDEX IF NOT EXISTS idx_address_block 
            ON transactions(from_address, block_number);
        
        -- Таблица для хранения состояния
        CREATE TABLE IF NOT EXISTS state (
            key TEXT PRIMARY KEY,
            value TEXT NOT NULL
        );
    )";
    
    char* err_msg = nullptr;
    int rc = sqlite3_exec(db_, sql, nullptr, nullptr, &err_msg);
    if (rc != SQLITE_OK) {
        throw std::runtime_error("Failed to initialize database: " + std::string(err_msg));
    }
}

bool Storage::insertTransactions(const std::vector<Transaction>& transactions) {
    std::lock_guard<std::mutex> lock(db_mutex_);
    
    const char* sql = R"(
        INSERT OR IGNORE INTO transactions 
        (block_number, block_hash, tx_hash, from_address, to_address, value, timestamp)
        VALUES (?, ?, ?, ?, ?, ?, ?)
    )";
    
    sqlite3_stmt* stmt;
    sqlite3_prepare_v2(db_, sql, -1, &stmt, nullptr);
    
    // Начинаем транзакцию для производительности
    sqlite3_exec(db_, "BEGIN TRANSACTION", nullptr, nullptr, nullptr);
    
    bool success = true;
    for (const auto& tx : transactions) {
        sqlite3_bind_int64(stmt, 1, tx.block_number);
        sqlite3_bind_text(stmt, 2, tx.block_hash.c_str(), -1, SQLITE_STATIC);
        sqlite3_bind_text(stmt, 3, tx.tx_hash.c_str(), -1, SQLITE_STATIC);
        sqlite3_bind_text(stmt, 4, tx.from_address.c_str(), -1, SQLITE_STATIC);
        sqlite3_bind_text(stmt, 5, tx.to_address.c_str(), -1, SQLITE_STATIC);
        sqlite3_bind_text(stmt, 6, tx.value.c_str(), -1, SQLITE_STATIC);
        sqlite3_bind_int64(stmt, 7, tx.timestamp);
        
        int rc = sqlite3_step(stmt);
        if (rc != SQLITE_DONE && rc != SQLITE_CONSTRAINT) {
            // SQLITE_CONSTRAINT = дубликат (игнорируем)
            success = false;
        }
        
        sqlite3_reset(stmt);
    }
    
    sqlite3_exec(db_, "COMMIT", nullptr, nullptr, nullptr);
    sqlite3_finalize(stmt);
    
    return success;
}

uint64_t Storage::getLastProcessedBlock() {
    std::lock_guard<std::mutex> lock(db_mutex_);
    
    const char* sql = "SELECT value FROM state WHERE key = 'last_block'";
    sqlite3_stmt* stmt;
    sqlite3_prepare_v2(db_, sql, -1, &stmt, nullptr);
    
    uint64_t result = 0;
    if (sqlite3_step(stmt) == SQLITE_ROW) {
        result = std::stoull(
            reinterpret_cast<const char*>(sqlite3_column_text(stmt, 0))
        );
    }
    
    sqlite3_finalize(stmt);
    return result;
}

std::vector<Transaction> Storage::findTransactions(
    const std::optional<std::string>& address,
    const std::optional<uint64_t>& from_block,
    const std::optional<uint64_t>& to_block,
    size_t limit,
    const std::optional<std::string>& cursor
) {
    std::lock_guard<std::mutex> lock(db_mutex_);
    
    std::string sql = "SELECT block_number, block_hash, tx_hash, from_address, "
                      "to_address, value, timestamp FROM transactions WHERE 1=1";
    
    // Построение WHERE условий
    if (address) {
        sql += " AND (from_address = ? OR to_address = ?)";
    }
    if (from_block) {
        sql += " AND block_number >= ?";
    }
    if (to_block) {
        sql += " AND block_number <= ?";
    }
    if (cursor) {
        // cursor = последний tx_hash из предыдущего запроса
        sql += " AND tx_hash > ?";
    }
    
    sql += " ORDER BY block_number ASC, tx_hash ASC LIMIT ?";
    
    sqlite3_stmt* stmt;
    sqlite3_prepare_v2(db_, sql.c_str(), -1, &stmt, nullptr);
    
    int param = 1;
    if (address) {
        sqlite3_bind_text(stmt, param++, address->c_str(), -1, SQLITE_STATIC);
        sqlite3_bind_text(stmt, param++, address->c_str(), -1, SQLITE_STATIC);
    }
    if (from_block) {
        sqlite3_bind_int64(stmt, param++, *from_block);
    }
    if (to_block) {
        sqlite3_bind_int64(stmt, param++, *to_block);
    }
    if (cursor) {
        sqlite3_bind_text(stmt, param++, cursor->c_str(), -1, SQLITE_STATIC);
    }
    sqlite3_bind_int64(stmt, param++, limit);
    
    std::vector<Transaction> result;
    while (sqlite3_step(stmt) == SQLITE_ROW) {
        Transaction tx;
        tx.block_number = sqlite3_column_int64(stmt, 0);
        tx.block_hash = reinterpret_cast<const char*>(sqlite3_column_text(stmt, 1));
        tx.tx_hash = reinterpret_cast<const char*>(sqlite3_column_text(stmt, 2));
        tx.from_address = reinterpret_cast<const char*>(sqlite3_column_text(stmt, 3));
        tx.to_address = reinterpret_cast<const char*>(sqlite3_column_text(stmt, 4));
        tx.value = reinterpret_cast<const char*>(sqlite3_column_text(stmt, 5));
        tx.timestamp = sqlite3_column_int64(stmt, 6);
        result.push_back(tx);
    }
    
    sqlite3_finalize(stmt);
    return result;
}
Производительность: Использование BEGIN TRANSACTION и COMMIT позволяет вставлять множество транзакций за одну операцию записи на диск, что значительно быстрее.

3.5. HTTP Server

Проблема/Контекст

Нужно предоставить REST API для поиска транзакций. Пользователи должны иметь возможность фильтровать по адресу, диапазону блоков, использовать пагинацию через cursor.

Решение

Используем Boost.Beast для создания HTTP сервера. Обрабатываем GET запросы к /transactions с query параметрами.

Разбор синтаксиса

#include <boost/beast.hpp>
#include <boost/asio.hpp>
#include <nlohmann/json.hpp>

namespace http = boost::beast::http;

class HttpServer {
public:
    HttpServer(
        net::io_context& io,
        Storage& storage,
        unsigned short port = 8080
    );
    
    void start();
    
private:
    class Session : public std::enable_shared_from_this<Session> {
    public:
        Session(tcp::socket socket, Storage& storage);
        void start();
        
    private:
        boost::asio::awaitable<void> readRequest();
        boost::asio::awaitable<void> handleRequest();
        void sendResponse(const json& data);
        
        tcp::socket socket_;
        Storage& storage_;
        beast::flat_buffer buffer_;
        http::request<http::string_body> request_;
    };
    
    void doAccept();
    
    net::io_context& io_;
    Storage& storage_;
    tcp::acceptor acceptor_;
};

Как это работает?

void HttpServer::doAccept() {
    acceptor_.async_accept(
        [this](boost::system::error_code ec, tcp::socket socket) {
            if (!ec) {
                std::make_shared<Session>(std::move(socket), storage_)->start();
            }
            doAccept();  // принимаем следующее соединение
        }
    );
}

boost::asio::awaitable<void> HttpServer::Session::readRequest() {
    http::request<http::string_body> req;
    co_await http::async_read(socket_, buffer_, req);
    request_ = std::move(req);
    co_await handleRequest();
}

boost::asio::awaitable<void> HttpServer::Session::handleRequest() {
    // Парсим URL и query параметры
    std::string target = request_.target();
    
    if (target.find("/transactions") != 0) {
        sendError(404, "Not Found");
        co_return;
    }
    
    // Извлекаем query параметры
    auto pos = target.find('?');
    std::map<std::string, std::string> params;
    if (pos != std::string::npos) {
        std::string query = target.substr(pos + 1);
        // Простой парсинг (можно использовать библиотеку)
        std::istringstream iss(query);
        std::string pair;
        while (std::getline(iss, pair, '&')) {
            auto eq_pos = pair.find('=');
            if (eq_pos != std::string::npos) {
                std::string key = pair.substr(0, eq_pos);
                std::string value = pair.substr(eq_pos + 1);
                // URL decode (упрощённо)
                params[key] = value;
            }
        }
    }
    
    // Парсим параметры
    std::optional<std::string> address;
    std::optional<uint64_t> from_block, to_block;
    size_t limit = 100;
    std::optional<std::string> cursor;
    
    if (params.count("address")) {
        address = params["address"];
    }
    if (params.count("from_block")) {
        from_block = std::stoull(params["from_block"]);
    }
    if (params.count("to_block")) {
        to_block = std::stoull(params["to_block"]);
    }
    if (params.count("limit")) {
        limit = std::stoull(params["limit"]);
        limit = std::min(limit, size_t(1000));  // максимум 1000
    }
    if (params.count("cursor")) {
        cursor = params["cursor"];
    }
    
    // Выполняем запрос к БД
    auto transactions = storage_.findTransactions(
        address, from_block, to_block, limit, cursor
    );
    
    // Формируем JSON ответ
    json response = json::array();
    for (const auto& tx : transactions) {
        response.push_back({
            {"block_number", tx.block_number},
            {"block_hash", tx.block_hash},
            {"tx_hash", tx.tx_hash},
            {"from_address", tx.from_address},
            {"to_address", tx.to_address},
            {"value", tx.value},
            {"timestamp", tx.timestamp}
        });
    }
    
    // Если есть ещё данные, добавляем cursor для следующей страницы
    if (transactions.size() == limit && !transactions.empty()) {
        json meta = {{"next_cursor", transactions.back().tx_hash}};
        response.push_back({{"_meta", meta}});
    }
    
    sendResponse(response);
}

void HttpServer::Session::sendResponse(const json& data) {
    http::response<http::string_body> res;
    res.result(http::status::ok);
    res.set(http::field::content_type, "application/json");
    res.body() = data.dump();
    res.prepare_payload();
    
    http::async_write(
        socket_,
        res,
        [self = shared_from_this()](boost::system::error_code ec, std::size_t) {
            // Соединение закроется автоматически
        }
    );
}

4. Интеграция компонентов

Главный файл (main.cpp)

#include <boost/asio.hpp>
#include <iostream>
#include <signal.h>

int main() {
    try {
        // 1. Создаём io_context для асинхронных операций
        net::io_context io;
        
        // 2. Инициализируем компоненты
        Storage storage("transactions.db");
        storage.initialize();
        
        RpcClient rpc_client(io, "localhost", "8545", "/");
        
        BlockFetcher fetcher(io, rpc_client, storage, 2000);
        
        HttpServer http_server(io, storage, 8080);
        
        // 3. Запускаем все компоненты
        fetcher.start();
        http_server.start();
        
        // 4. Обработка сигналов для graceful shutdown
        boost::asio::signal_set signals(io, SIGINT, SIGTERM);
        signals.async_wait([&](boost::system::error_code, int) {
            std::cout << "Shutting down..." << std::endl;
            fetcher.stop();
            io.stop();
        });
        
        // 5. Запускаем обработку блоков в отдельном потоке
        std::thread block_processor([&]() {
            auto& block_channel = fetcher.getBlockChannel();
            TransactionParser parser;
            
            while (true) {
                boost::system::error_code ec;
                json block_json;
                block_channel.async_receive(
                    [&](boost::system::error_code e, json b) {
                        ec = e;
                        block_json = b;
                    }
                );
                io.run_one();  // ждём получения блока
                
                if (ec) break;  // канал закрыт
                
                // Парсим и сохраняем транзакции
                auto transactions = TransactionParser::parseBlock(block_json);
                if (!transactions.empty()) {
                    storage.insertTransactions(transactions);
                    
                    // Обновляем последний обработанный блок
                    uint64_t block_num = transactions[0].block_number;
                    storage.updateLastProcessedBlock(block_num);
                }
            }
        });
        
        // 6. Запускаем io_context (блокирующий вызов)
        std::cout << "Server started on port 8080" << std::endl;
        io.run();
        
        block_processor.join();
        
    } catch (const std::exception& e) {
        std::cerr << "Error: " << e.what() << std::endl;
        return 1;
    }
    
    return 0;
}
Архитектура: Все компоненты работают асинхронно через один io_context, что позволяет эффективно использовать ресурсы и обрабатывать множество операций параллельно.

5. Требования к производительности

5.1. Обработка 50+ блоков в секунду

Проблема

Нужно обрабатывать минимум 50 блоков в секунду. В Ethereum блок содержит в среднем 100-200 транзакций, значит нужно обрабатывать ~5000-10000 транзакций в секунду.

Решение

  • Параллельная обработка блоков: Используем thread pool для парсинга нескольких блоков одновременно
  • Батчинг в БД: Вставляем транзакции батчами через одну транзакцию БД
  • Асинхронный I/O: Все сетевые операции неблокирующие
// Пример параллельной обработки блоков
class BlockProcessor {
    boost::asio::thread_pool pool_{4};  // 4 потока для обработки
    
    void processBlock(const json& block_json) {
        boost::asio::post(pool_, [this, block_json]() {
            auto transactions = TransactionParser::parseBlock(block_json);
            if (!transactions.empty()) {
                storage_.insertTransactions(transactions);
            }
        });
    }
};

5.2. Отсутствие утечек памяти

Решение

  • Используем умные указатели (std::shared_ptr, std::unique_ptr)
  • RAII для ресурсов (сокеты, соединения БД)
  • Ограничиваем размер очередей (channel capacity)

6. Обработка ошибок и надёжность

6.1. Retry при ошибках RPC

boost::asio::awaitable<std::optional<json>> 
RpcClient::callWithRetry(const std::string& method, const json& params, int max_retries = 3) {
    for (int i = 0; i < max_retries; ++i) {
        auto result = co_await call(method, params);
        if (result) {
            co_return result;
        }
        
        // Экспоненциальная задержка перед повтором
        auto delay = std::chrono::milliseconds(100 * (1 << i));
        co_await net::steady_timer(io_, delay).async_wait();
    }
    
    co_return std::nullopt;
}

6.2. Graceful Shutdown

При получении SIGINT/SIGTERM сервис должен:

  1. Остановить получение новых блоков
  2. Дождаться завершения текущих операций
  3. Закрыть соединения с БД
  4. Корректно завершить работу

7.1. Обработка реоргов (Chain Reorgs)

Иногда блокчейн может "откатиться" — блок, который считался валидным, становится невалидным. Нужно отслеживать это и удалять транзакции из невалидных блоков. 

void Storage::handleReorg(uint64_t from_block) {
    // Удаляем все транзакции начиная с from_block
    const char* sql = "DELETE FROM transactions WHERE block_number >= ?";
    sqlite3_stmt* stmt;
    sqlite3_prepare_v2(db_, sql, -1, &stmt, nullptr);
    sqlite3_bind_int64(stmt, 1, from_block);
    sqlite3_step(stmt);
    sqlite3_finalize(stmt);
}
