## Покрытие настроек и основания

В полном справочнике есть отдельная строка-якорь для каждого канонического поля tracked source-data/Settings.json; набор автоматически сопоставлен с ключами файла. Для каждого указаны допустимые значения, шаблон, значение при отсутствии, связь и конкретная проверка. Общий момент применения приведён один раз.

Активный путь: SearchEngineApplication::start → ConverterJSON::getSettings → validateSettings → настройки SearchServer, Telega, watcher/scheduler, SQLiteIndexSerializer. Проверка Configure/Install: tools/config/main.cpp. Старый Settings::getSettings, наличие неиспользуемых функций и архивные копии не считаются доказательством рабочего поведения. Прямой startup проверяет наличие Settings до общего parser fallback.

Обновление/применение: deployment управляющие BAT и tools/config/RuntimeDataTransaction; исходный Restart содержит 1800 секунд и no forced process termination. Архивные сценарии сверены с tools/archive; авторизация — access_setup/token_issuer, AsioServer, AuthRuntime. Протокол не изменялся.

## Исправления смысла и ограничения программы

- Исправлены противоречивые обещания memory как fresh-default и force-kill Restart за 120 секунд; новая установка предлагает sqlite, Restart ждёт до 1800 без force-kill.
- Уточнён приоритет старого port над asio_port; query_word_match отсутствует → any, хотя в шаблоне all.
- Различены defaults кода и шаблона: memory/sqlite, scan_on_startup, PRM autodetect, timeout, max_response, port и threads.
- Отсутствующий ind_time дополняется 0 и затем не проходит startup ≥1; программа не исправлялась. Безопасный совет — сохранять явное положительное значение.
- При неполном файле каноническое пересохранение может убрать неизвестные поля; aliases или отсутствие server_mode/месячных полей сами по себе не заставляют переписывать файл.
- Таймаут ожидания файла не обещает принудительную отмену работы; очередь batch не является потолком всей RAM; sqlite_load_threads ограничен 1…16.
- ignore.txt используется активной обработкой описи как список подразделений, а не исключаемых слов поиска. Backup.json не объявлен настройкой поиска. Эти ограничения описаны отдельно, поведение не менялось.

## Дополнительная сверка активных сценариев

- Telega::isSourceConfigured: active требует общий корень, archive принимает общий или явный месячный. При отсутствии месячных баз за прошлый год active может вернуться к ARCHIVE.db3. В выключенном источнике SQL даёт обычный пустой результат, недоступный включённый источник — отдельную ошибку; текстовые карточки выключенного типа пропускаются.
- AddFileCommand создаёт обработку описи только при enable_prm_short_content_autodetect; OUT — подстрока любого участка пути. ignore.txt — список подразделений для описи, не стоп-слова поиска. Краткое содержание PRM обновляется до фильтра подразделения.
- prefix_map.json перечитывается на каждый GET_ATTACHMENTS; prefix и строка map соединяются без автоматического разделителя, имя пользователя сравнивается точно. Все связанные поля и пример перенесены в серверный справочник файлов.
