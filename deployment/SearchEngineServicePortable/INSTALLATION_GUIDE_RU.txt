SearchEngineConfig.exe не является сервером и не устанавливает службу сам.
BAT-файлы вызывают его для безопасной работы с UTF-8 JSON, определения числа
процессоров, проверки ограничений, свободного порта, резервного копирования и
протокольной проверки PING/PONG. Диалог настройки также выполняется внутри
SearchEngineConfig.exe, поэтому русский текст корректно отображается и на
Windows 7 независимо от кодировки BAT-файла.

На машине сборки PowerShell используется только упаковщиком. На целевом
компьютере все версии комплекта работают через BAT и штатные средства Windows.

2. ЧТО СДЕЛАТЬ ДО ЗАПУСКА
-------------------------

1) Распаковать или скопировать комплект на локальный диск. Не запускать прямо
   из архива и не копировать только отдельные файлы.
2) Открыть data\Settings.json обычным текстовым редактором. Это шаблон релиза
   (template/schema/default values), а не production-конфиг уже работающей
   службы. Его можно подготовить под целевой компьютер до установки; активный
   Settings.json создаётся в ProgramData после диалога настройки.
3) Подготовить понятные идентификаторы экземпляров. Для серверов разных годов
   или с разными наборами индексируемых папок используйте разные имена,
   например year2025 и year2026. Установщик спросит имя при запуске.
4) Проверить config.index_roots — список индексируемых каталогов.
   Допустимы абсолютные локальные Windows-пути или UNC, например
   D:\DATA и \\server\share\DATA. Каталог может ещё не существовать
   (late-root). UNC синтаксически принимается, но учётка службы должна
   реально иметь доступ к SMB/share/ACL; LocalSystem не гарантированно
   имеет такой доступ.
5) Проверить config.excluded_subtrees — исключаемые подкаталоги.
   Тот же path-contract: абсолютный локальный путь или UNC.
   Старые имена dirs / exclude_dirs читаются только как compatibility aliases
   при миграции; в новом шаблоне используйте canonical-имена.
6) Проверить config.indexed_extensions — точные последние расширения без точки.
   Сравнение не зависит от регистра: txt принимает file.txt и FILE.TXT, но не
   file.mytxt. config.include_extensionless_files отдельно разрешает файлы без
   расширения (например README и .hidden). Пустой indexed_extensions допустим
   только при include_extensionless_files=true.
7) Проверить config.query_word_match: all требует наличия всех слов запроса,
   any выбирает документы хотя бы с одним найденным словом. Старые extensions
   и exact_search читаются только как compatibility aliases; explicit
   configure/update сохраняет только canonical-имена.
8) Проверить prm_base_dir и prd_base_dir — каталоги баз PRM/PRD.
9) Проверить tlg_send_root, razn_output_dir, opis_base_dir и f12_base_dir.
   Это отдельные production-корни и по текущему контракту валидации —
   только абсолютные локальные Windows-пути (UNC не принимается).
   Физически они могут отсутствовать, если соответствующая функция сейчас
   не используется; ошибка появится при вызове.
10) Для локальных index_roots установщик может предупредить, если каталог
   не найден, и по умолчанию предложит отменить установку. Это проверка
   доступа на этапе install, а не требование, чтобы каждый корень уже
   существовал. Mapped drives пользовательской сессии (например Z:\...)
   для службы не использовать.
11) Для каждого экземпляра выбрать отдельный свободный TCP-порт.
12) Запустить Install-SearchEngineService.bat от имени администратора.

Каталог logs\ в комплекте отсутствует: это runtime-состояние и создаётся в
data-dir при установке или обновлении, когда это нужно. Каталог messages\ в
комплекте также отсутствует (legacy MessageQueue снят с runtime). Новая
установка messages\ не создаёт; при обновлении существующий historical
messages\ в ProgramData сохраняется и не удаляется автоматически.

Служба работает как LocalSystem. Mapped drives пользовательской сессии
(например Z:\...) не использовать для службы: они недоступны LocalSystem.
config.index_roots и config.excluded_subtrees принимают абсолютный локальный
Windows-путь или UNC. Production-корни (tlg_send_root, razn_output_dir,
opis_base_dir, f12_base_dir) — только абсолютные локальные Windows-пути;
UNC для них не принимается. UNC index_roots синтаксически поддерживается,
но service account должен реально иметь доступ к SMB/share/ACL; LocalSystem
не гарантированно имеет такой доступ. Буква диска сама по себе не доказывает,
что это физический локальный том.

Год, порт, потоки, таймаут и режим document_catalog_storage необязательно
редактировать вручную: установщик
сформирует окончательный Settings.json в ProgramData, не изменяя переносимый
шаблон.

Установщик обязательно спросит, где хранить каталог документов. Enter выбирает
`memory` (быстрее, пути и метаданные находятся в RAM). Вариант `sqlite`
уменьшает расход RAM, но может добавить небольшую задержку при выдаче top-N.
При переустановке импортированный режим становится предлагаемым по умолчанию;
после изменения режима требуется Stop → Start.

data\Settings.json является изменяемым пользовательским шаблоном и намеренно
не защищён контрольной суммой пакета, как и остальные файлы в data\. Его можно
заменить конфигурацией этого компьютера. Установщик проверяет JSON уже после
диалога настройки, на сформированном файле, а не на шаблоне в комплекте.

2.1. НЕСКОЛЬКО СЕРВЕРОВ НА ОДНОМ ПК
------------------------------------

При обычном запуске без аргументов установщик сначала спрашивает идентификатор
экземпляра и показывает подсказку о серверах разных годов и каталогах
индексирования. Идентификатор default сохраняет полную совместимость со старой
установкой:

  служба:       SearchEngineService
  display name: Search Engine ASIO Server
  программа:    Program Files\SearchEngineService
  данные:       C:\ProgramData\SearchEngineService

Для идентификатора archive установщик использует:

  служба:       SearchEngineService-archive
  display name: Search Engine ASIO Server (archive)
  программа:    Program Files\SearchEngineService-archive
  данные:       C:\ProgramData\SearchEngineService-archive
  firewall:     SearchEngineService-archive TCP

Допустимы 1–32 символа: латинские буквы, цифры, дефис и подчёркивание; первый
символ должен быть буквой или цифрой. Для автоматического запуска имя можно
заранее записать в ServiceInstance.cmd или передать аргументом вместе с
необязательными флагами:

  Install-SearchEngineService.bat archive
  Install-SearchEngineService.bat /SkipVcRedist
  Install-SearchEngineService.bat /SkipVcRedist archive

Для stop, start, restart и uninstall нужно использовать тот же идентификатор.

Поддерживаемые флаги установщика:

  /validate       только проверка SHA-256 пакета, без установки;
  /SkipVcRedist   не спрашивать и не запускать установщик VC++ Runtime
                  (для автоматизации, когда runtime уже гарантирован).

Без /SkipVcRedist на шаге Runtime установщик сам спрашивает: поставить
packaged redistributable или пропустить шаг. Если ключевые CRT DLL уже
найдены, рекомендуется пропуск; иначе — установка.

У каждого экземпляра обязательны отдельный порт, каталог данных и индекс.
Каталоги индексируемых документов могут быть разными или пересекаться — это
задаётся config.index_roots каждого Settings.json.

3. ДИАЛОГ НАСТРОЙКИ
-------------------

Первые вопросы — язык интерфейса помощника и идентификатор экземпляра службы:

  1 — Русский (по умолчанию);
  2 — English.

Можно просто нажать Enter — будет выбран русский язык. В следующих вопросах
Enter или вариант 1 принимает рекомендуемое значение, вариант 2 позволяет
ввести своё. Ввод и допустимый диапазон проверяются самим EXE-помощником.

Порт ASIO
  Диапазон 1..65535. После остановки старой службы установщик проверяет, что
  порт можно занять. Правило Windows Firewall привязывается к этому порту.

Рабочий год
  По умолчанию текущий системный год. Разрешён диапазон 2000..2099.

Исполнительные потоки
  Рекомендация: min(число логических процессоров, 8), но не меньше 2.
  Ввести 1 нельзя: один поток может занять плановое обновление и оставить без
  исполнителя индексирование и сетевые команды. Верхняя граница — два числа
  логических процессоров, дополнительно не более 32 для x86 и 64 для x64.

Таймаут индексации одного файла
  Рекомендация 120 секунд, допустимо 10..600. Настройка записывается как
  config.file_indexing_timeout_sec.

Краткое содержание AutoPad PRM
  По умолчанию включено. При отключении новые файлы индексируются как обычно,
  но поле краткого содержания PRM автоматически не изменяется. Специальной
  обработки .zag в SearchEngine больше нет: она выполняется отдельным проектом
  ZagEditor. Настройка:
  config.enable_prm_short_content_autodetect.

Помощник также рассчитывает max_parallel_readers и sqlite_load_threads из
выбранного числа потоков и возможностей компьютера.

4. ЧИСТАЯ УСТАНОВКА
-------------------

Установщик:

1) проверяет SHA-256 и архитектуру содержимого пакета;
2) обеспечивает VC++ Runtime best-effort: в интерактивном режиме спрашивает,
   ставить ли packaged redistributable (если CRT DLL уже найдены — рекомендует
   пропуск; иначе — установку). Флаг /SkipVcRedist пропускает вопрос. При сбое
   quiet-установщика предлагает продолжить (SearchEngineConfig к этому моменту
   уже успешно запускался) или отменить;
3) проверяет настройки и свободный TCP-порт;
4) копирует программу в отдельный каталог выбранного экземпляра;
5) копирует изменяемые данные в отдельный ProgramData-каталог экземпляра;
6) регистрирует SearchEngineService[-instance] с Automatic (Delayed Start);
7) настраивает три попытки восстановления службы и preshutdown до 3 минут;
8) добавляет firewall rule;
9) запускает службу и ждёт не только RUNNING, но и настоящий ответ PONG.

Служба работает как LocalSystem. Runtime-пути должны быть доступны этому
аккаунту по ACL. Mapped drives пользовательской сессии службе недоступны.
Буква диска сама по себе не доказывает, что это физический локальный том.
index_roots / excluded_subtrees могут быть UNC, если учётка службы имеет
доступ к share; production-корни ниже — только локальные абсолютные пути.

Production-корни задаются в Settings.json:

- tlg_send_root — LOAD_TLG_TO_SEND, далее <корень>\<МЕСЯЦ>\<ДАТА>\...
- razn_output_dir — LOAD_RAZN
- opis_base_dir — GET_OPIS_BASE (<каталог>\<год>.db) и RecordProcessor
  (<каталог>\<год>.DB)
- f12_base_dir — GET_VH_TELEGA_WAY / GET_ISH_TELEGA_WAY
  (<каталог>\<год>.db и <каталог>\base.db)

Отсутствие feature-specific источника не обязано ломать startup SearchEngine.
Ошибка проявляется при вызове соответствующей функции.

5. БЕЗОПАСНАЯ ПЕРЕУСТАНОВКА
---------------------------

Если служба уже существует, установщик предлагает переустановку. Можно выбрать:

1) полный экспорт программы и всех данных;
2) экспорт Settings.json и логов;
3) продолжение без экспорта — только после отдельного подтверждения.

Export является добровольной внешней копией оператора. ProgramData при обычном
update сохраняется независимо от этого выбора: индекс, авторизация, messages,
logs, prefix_map.json, пользовательский ignore.txt и неизвестные runtime-файлы
остаются на месте. Отказ от export больше не означает, что они будут удалены
после health-check.

Для экспорта укажите диск или каталог, например E:\Backups. Помощник проверяет,
что назначение не находится внутри удаляемых каталогов и что свободного места
достаточно. Архив создаётся в отдельной папке с датой и временем.

После остановки службы заменяется только Program Files. ProgramData остаётся
на своём месте. Новый Settings.json формируется из шаблона нового релиза с
рекурсивным импортом существующих установленных значений: старые поля
сохраняются, новые поля релиза получают defaults из шаблона, если их не было в
старом конфиге; явные значения диалога настройки имеют приоритет над template.
OEM866.INI и client-endpoint.txt публикуются
атомарно и входят в малую rollback-транзакцию. Пользовательский ignore.txt не
перезаписывается. При ошибке запуска или PING/PONG установщик возвращает старое
приложение, прежние managed-файлы, правило firewall старого порта и прежнюю
службу. Rollback не копирует и не перемещает многогигабайтный индекс.
Полное удаление ProgramData по-прежнему выполняется только явным uninstall
после предупреждения.

6. ОСТАНОВКА, ЗАПУСК И ПЕРЕЗАПУСК
---------------------------------

Stop-SearchEngineService.bat и Start-SearchEngineService.bat — штатная пара
остановки и последующего запуска Windows-службы. Это не Pause/Continue: служба
их не поддерживает. После Stop → Start создаётся новый процесс SearchEngine, и
SearchEngineApplication::start() заново читает рабочий
C:\ProgramData\SearchEngineService[-instance]\Settings.json и инициализирует
runtime-ресурсы. Отдельной «перезагрузки конфигурации» в C++ не требуется.

Stop-SearchEngineService.bat:

- требует права администратора;
- ждёт штатный STOPPED до 1800 секунд (корректное закрытие индекса и фона);
- если служба уже STOPPED — завершается успешно;
- не вызывает taskkill и не предлагает принудительное завершение.

Start-SearchEngineService.bat:

- проверяет установленный Settings.json через SearchEngineConfig.exe;
- при уже RUNNING всё равно выполняет PING/PONG;
- после start ждёт RUNNING и проверяет PING/PONG (таймаут 10 секунд) на порту
  из установленного Settings.json, а не из шаблона data\Settings.json пакета;
- не изменяет Windows Firewall и не трогает клиентскую базу;
- предупреждает, если порт Settings.json отличается от client-endpoint.txt
  или от существующего правила установки firewall.

Остановленная служба с Automatic / Delayed Start снова запустится после
перезагрузки Windows. Для долговременного отключения отдельно переведите
Startup Type в Manual или Disabled — Stop/Start это автоматически не делают.

Configure-SearchEngineService.bat — безопасный способ изменить Settings.json
установленной службы с полным rollback при неудаче:

- получает фактический data-dir через SCM (не предполагает %ProgramData%);
- открывает копию Settings.json в Notepad для редактирования;
- проводит через валидацию (SearchEngineConfig validate) как обязательный шаг;
- выполняет Stop → атомарная замена → Start → ожидание RUNNING → PING/PONG;
- при изменении порта автоматически обновляет client-endpoint.txt и правило
  Windows Firewall;
- при любой ошибке делает побайтовый rollback настроек, восстанавливает правило
  брандмауэра и перезапускает службу на старом порту с проверкой PING/PONG.

Hot reload не поддерживается — всегда Stop → Start. Требует Administrator.

Archive-SearchEngineService.bat запускает отдельный мастер годового архива.
Первый пункт меню переносит год без установленной службы и ничего не
останавливает. Он копирует месячные базы и файлы, проверяет SQLite/SHA-256,
меняет DirectTo только в архивных копиях и затем предлагает отдельную очистку
неизменившихся исходников.

Во всех интерактивных вопросах о каталоге можно ввести путь вручную или нажать
Enter и выбрать существующую папку в стандартном диалоге Windows 7. Для
необязательных каталогов месячных баз одиночный знак `-` отключает источник.
Аргументы командной строки используются напрямую и диалог выбора не открывают.

Для источника D:\TLG переносится его обычное содержимое верхнего уровня и
только папка года, равного архивируемому. Папка OUT в любом регистре, а также
все остальные папки с именем ровно из четырёх цифр пропускаются. Обычные папки
без четырёхзначного имени и обычные файлы копируются.

Пункт переноса службы сканирует SearchEngineService[-instance]. Он доступен
только при document_catalog_storage=sqlite: после остановки службы во временный
staging копируются весь каталог установки, data-dir, индексируемые каталоги и
базы, в копиях
исправляются docs.path и DirectTo. Только после всех проверок архив публикуется,
SCM ImagePath переключается на него, а Settings получает server_mode=archive.
Автоматическая индексация в этом режиме отключена. Ручной START_UPDATE_BASE
разрешён только точному имени admin и только с адреса 127.0.0.1.

Старые файлы не удаляются одновременно с переключением: сначала проверьте
поиск вручную. Утилита останется открытой и спросит, переходить ли к очистке
старого места. При отказе очистку можно позже выбрать отдельным пунктом меню;
перед удалением всё равно потребуются дополнительные подтверждения.
После проверки каталог установки удаляется целиком вместе с bin, tools,
документацией и ServiceInstance.cmd, а data-dir — вместе с логами и файлами
SQLite -wal/-shm/-journal. Успешная фаза записывается только после проверки,
что оба каталога действительно отсутствуют. Прерванную очистку можно повторить;
она также исправляет старые архивы, ошибочно помеченные как уже очищенные.
Декабрьская BASES_PRD `12-<year>.db3` никогда не удаляется автоматически.
Возврат в активный режим доступен как при сохранённом старом месте, так и после
его подтверждённой очистки.

После возврата утилита проверяет исходный SCM ImagePath, состояние RUNNING,
исходные программу и data-dir и отсутствие служб, использующих архив. Только
после этого manifest получает фазу restored-running. В интерактивном режиме
архивная копия удаляется лишь после отдельного подтверждения ручной проверки и
повторной проверки manifest, ImagePath, состояния службы и границ каталога.
Режим --yes архивную копию после возврата автоматически не удаляет.

Для применения нового порта вручную (без Configure-SearchEngineService.bat):

1) выполните Stop, затем Start (новый процесс слушает новый порт);
2) проверьте или пересоздайте inbound-правило Windows Firewall;
3) обновите параметры клиента (host/port / client-endpoint.txt).
   Служба и Start-скрипт клиентскую базу не меняют.

Изменение `document_catalog_storage` не требует изменения клиента. Выполните
Stop → Start: исправная SQLite-база сохраняет прежние `docId`, повторная
индексация не требуется.

Restart-SearchEngineService.bat по-прежнему выполняет stop+start подряд и ждёт
штатную остановку не более 120 секунд. Если служба зависла, Restart предлагает
принудительно завершить только PID этой службы. После запуска выполняется
PING/PONG с таймаутом 10 секунд. Для обычного применения конфигурации без
force-kill предпочитайте Stop, затем Start.

Ручные команды администратора:

  sc query SearchEngineService
  sc start SearchEngineService
  sc stop SearchEngineService

Для экземпляра archive:

  Stop-SearchEngineService.bat archive
  Start-SearchEngineService.bat archive
  Restart-SearchEngineService.bat archive
  sc query SearchEngineService-archive

Логи:

  C:\ProgramData\SearchEngineService[-instance]\logs

7. ПОЛНОЕ УДАЛЕНИЕ
------------------

Запускайте Uninstall-SearchEngineService.bat из переносимого комплекта от имени
администратора. Без аргумента он сканирует зарегистрированные службы
SearchEngineService[-instance], показывает нумерованный список и предлагает
выбрать удаляемую. Затем он предлагает полный экспорт, экспорт настроек и логов
либо отказ от экспорта с дополнительным подтверждением. Для автоматизации
экземпляр по-прежнему можно передать аргументом.

После успешного экспорта и подтверждения удаляются:

- регистрация выбранного SearchEngineService[-instance];
- правило Windows Firewall;
- его отдельный Program Files\SearchEngineService[-instance];
- его отдельный C:\ProgramData\SearchEngineService[-instance] со Settings.json, индексом, базами,
  сообщениями и логами.

Пути программы и data-dir берутся из фактического SCM ImagePath. Если служба
работает из замороженного архива, удаляется весь активный каталог архива
вместе с program, data, content, autopad и manifest. Дополнительно удаляются
остатки этого экземпляра в стандартных Program Files и ProgramData.

После получения STOPPED скрипт дополнительно ждёт завершения PID процесса.
Удаление основных и rollback-каталогов повторяется не менее 30 секунд, включая
снятие атрибутов read-only/system/hidden. Если каталог продолжает удерживаться,
можно закрыть Explorer, Total Commander или программу работы с базами и выбрать
повторную попытку. Регистрация службы удаляется только после файлов. Скрипт
сообщает об успехе только если каталоги действительно исчезли. Если от старого
или прерванного удаления остались каталоги уже незарегистрированной службы,
установщик новой версии покажет их точные пути и предложит явно удалить остатки
перед установкой.

Перед запуском удаления закройте окно «Службы» (services.msc), Event Viewer и
другие консоли управления: открытый handle может оставить регистрацию в
состоянии «помечена на удаление». Скрипт ждёт фактического исчезновения ключа
службы и предлагает повторить проверку после закрытия таких окон. Последний
диагностический отчёт записывается в
%TEMP%\SearchEngineService-Uninstall-last.log. Итоговое окно закрывается только
после явного нажатия клавиши 0.

8. НАСТРОЙКА НОВОГО MULTI-SERVER КЛИЕНТА
-----------------------------------------

Windows service name нужен только локальной Windows. Клиенту требуются:

- уникальный server_id (рекомендуется равный instance id);
- host — имя или IP компьютера;
- god и port в server_ports;
- enabled=1 в обеих таблицах.

Установщик записывает эти значения-подсказки в
C:\ProgramData\SearchEngineService[-instance]\client-endpoint.txt. Файл можно
передать администратору клиента; база Settings.db3 автоматически не меняется.

Например, для служб SearchEngineService-main и SearchEngineService-archive на
одном ПК клиенту задаются server_id main/archive, одинаковый host и разные
порты. Клиент выполняет поиск по обоим адресам и сохраняет server_id как
источник результата.

При ошибке экспорта удаление не начинается. При зависшей остановке сначала
появляется явный выбор принудительного завершения процесса или отмены.
